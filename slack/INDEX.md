## 분류·검증 규칙

- 메시지를 채널명만으로 분류하지 않고 본문의 목적에 따라 분류한다.
- 사실, 작성자의 계획·제안, 완료 보고, 미확인을 구분한다. 담당자·기한·완료 상태를 추측하지 않는다.
- 기존 공식 문서와 충돌하는 공지는 출처와 조건을 기록한다. 최종 합의 근거 없이 팀장·주제·제출 상태를 바꾸지 않는다.
- 외부 자료 URL과 확인 날짜를 남긴다. Slack에서 URL을 봤다는 사실과 외부 페이지·기능 검증을 구분한다.
- 기존 문서를 찾아 링크하고, 첨부 본문·해시가 없으면 파일의 동일성이나 수정 내용을 확정하지 않는다.
- 분류 문서는 초기 백업의 메시지 날짜로 이름을 붙였다. 수집 날짜로 과거 공지를 새 공지처럼 만들지 않는다.
- raw는 보존하고 분류만 갱신한다. 원문과 분류 파일 해시는 [등록 상태](state/organization.json)에 기록한다.
- [최신 팀 Git 흐름](../팀-온보딩.md)에 따라 `yusang` → PR → 검사 → Merge pull request로 공개한다.
  `main`에 직접 push하지 않으며, 예약 시각은 매일 한국 시간 새벽 01:00이다.
