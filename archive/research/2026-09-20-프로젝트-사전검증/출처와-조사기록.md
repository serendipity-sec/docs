# 출처와 조사 기록

공통 확인일: **2026-09-20 (Asia/Seoul)**. 별도의 날짜가 있는 경우에는 발행일 또는 확인한 판본을 뜻한다. 동적 웹 문서에 발행일이 표시되지 않은 경우 추정하지 않았다.

## 1. 기록의 목적과 한계

이 기록은 네 문서의 주요 주장과 원문을 연결한다. 검색 결과의 짧은 설명만으로 제품 기능을 확정하지 않고, 논문 원문·공식 문서·공개 소스의 관련 부분을 확인했다. GitHub API로 주요 8개 저장소의 현재 커밋·릴리스를 확인하고, 선택 파일의 내용을 읽었다.

이 목록은 42개 **문서·논문·코드 항목**이다. 같은 제품의 서로 다른 문서도 포함하므로 독립 연구 42편이라는 뜻이 아니다. 원문 전체를 보존한 웹 아카이브나 체계적 문헌고찰의 완전한 검색 집합은 아니다. 보안 스캐너를 실행하거나 연구를 재현한 로그도 아니다.

자료의 역할을 구분한다.

- **관찰 연구**: 논문의 수집 대상·기간·분모와 함께 사용한다.
- **업체 운영 보고**: 배포·고객 사용 신호로 사용하며 독립 검증과 구분한다.
- **사양·소스**: 지원되는 형식·기능·제약의 근거다. 보급률이나 실제 성능의 근거는 아니다.
- **평가 방법 연구**: 평가 설계에 참고한다. 다른 분야의 효과 크기를 이 프로젝트에 그대로 대입하지 않는다.

## 6. 반복 조사 경로

정확한 검색 결과 총수나 제외 수를 사후에 만들어내지 않았다. 아래는 실제 진행한 주요 검색·원문 대조의 주제와 결과다.

| 단계 | 검색·확인한 내용 | 다시 조사하게 된 이유 | 결론에 반영한 것 |
|---|---|---|---|
| 1. 기존 자료 대조 | 저장소 제안서, 생태계·선행조사, 2026-09-19 통합조사 | 단순 개념 설명을 반복하지 않고 기존 주장 확인 | 이전 결론을 확정 사실로 복사하지 않음 |
| 2. 도입 근거 | AISI MCP 연구, Skills Night, Registry-to-Repository 원문 | 등록 수와 실제 도입을 구분할 필요 | 다운로드 대리 지표와 저장소 재사용의 차이 |
| 3. 다른 형식 보강 | `n8n community nodes verified security`, `Dify plugin signature verification installation`, n8n 고객 사례 | Skill·MCP 근거를 워크플로 전체로 일반화하지 않기 위해 | 업무 실행·유통 기능과 외부 재사용 비율 분리 |
| 4. 정보 공백 검증 | Agent Skills 사양, MCP Registry OpenAPI, Skills CLI 잠금 소스 | 선택 필드만 보고 “관리 수단 없음”이라 결론 내릴 수 없음 | 버전·출처·무결성의 기존 지원 확인 |
| 5. 경쟁 반대 근거 | Docker MCP, ToolHive Cedar, DefenseClaw, NVIDIA pipeline, AgentShield | 검사기만 비교하면 통합 제품의 기능을 놓침 | 증거 묶음·서명·권한 통제까지 비교 확대 |
| 6. 소스와 버전 확인 | 주요 8개 저장소 GitHub API와 선택 README·소스 | 현재 기능·릴리스·라이선스 혼동 방지 | SHA 기록, 0.5/0.6 구분, 기본 브랜치와 릴리스 분리 |
| 7. 성능 근거 검토 | ClawHub 논문 methods·label provenance·threats to validity | 불일치율을 정확도나 악성 비율로 오독할 가능성 | silver label과 독립 정답의 필요성 |
| 8. 사용자 효과의 반대 근거 | 권한 정책 실험, Bansal, Buçinca, Lakens | 좋은 설명·적은 질문이 자동으로 보안 향상인지 확인 | 위험 승인·과신·시간을 함께 측정하는 설계 |
| 9. 결과 대조 | 각 문서의 주장·범위·원문·실행 상태 점검 | 제안과 관측이 섞이는 것을 방지 | NOT_RUN 유지, 반증 조건과 후속 평가 명시 |

자료의 날짜는 “현재 시점”과 “관측 기간”을 구분했다. 2025년 pull 수, 2026년 초 데이터셋, 현재 default branch, 특정 제품 릴리스는 같은 시점의 시장 스냅샷이 아니다.

## 7. 사용하지 않거나 범위를 제한한 자료

| 자료·주장 | 처리 이유 |
|---|---|
| 등록 수·stars에서 계산한 시장 점유율 | 실행 사용자 분모가 없어 채택하지 않음 |
| 비공식 mirror의 n8n 문서 | 공식 GitHub의 현재 문서 경로로 다시 확인 |
| 검색된 개인 블로그·Reddit의 제품 설명 | 기술 기능 확정에는 제작사 사양·소스를 우선 사용 |
| GitHub issue에 달린 자동 응답의 설정 권고 | 실제 기능·보안 권고의 근거로 사용하지 않음 |
| Dify 예제 환경 파일의 샘플 비밀값 | 조사 결과에 복사하지 않음. 서명 관련 공식 설명만 사용 |
| 이전 문서의 “모든 스캐너 90% 이상 우회” 식 일반화 | 이번 범위에서 재현하지 않았고 버전·실험 조건을 시장 전체에 적용할 수 없음 |
| 과거 MCP-Scan 문서의 기능 | 선행 아이디어 확인에 한정하고 현재 CLI 지원과 분리 |
| Huel·기타 기업 사례 | 업무 사용 신호를 중복 나열하지 않고 외부 재사용 비율의 근거로도 쓰지 않음 |

조회 과정에서 n8n의 과거 `workflows/export-import` 경로와 SARIF의 잘못 추정한 스키마 경로가 유효하지 않음을 확인했다. 본문은 공식 저장소에서 다시 찾은 경로를 인용한다. 실패한 조회를 자료 확인 완료로 세지 않았다.

## 8. 다음 조사에서 필요한 새 증거

같은 검색을 반복해도 얻기 어려운 부분은 명확하다.

1. 우리 대상 사용자의 실제 도입·변경 사례와 기존 검토 과정.
2. 고정한 호스트에서 기존 도구 조합을 사용한 과업 수행 결과.
3. 독립적인 사례 판정과 평가 집합의 계보·중복 기록.
4. 동일 자료·엔진을 제공했을 때 우리 화면·근거 연결이 만드는 차이.
5. 구현한 경우에 한한 실제 사용 조건의 유지·강제 증거.

이 증거가 확보되기 전에는 “구조가 복잡하다”, “다른 스캐너가 다른 경고를 낸다”, “사용자가 더 신뢰한다고 답한다”를 각각 문제 규모·정답·보안 효과로 바꿔 쓰지 않는다.
