## 이번에 확보한 근거

- **논문 12편**을 비교했다. 핵심 결합 연구 5편은 SkillProbe, SkillReact, SCR-Bench, SkillFuzz, CompoSkill이다. AgentThread·CaMeL·Connor와 MCP 평가 논문도 대조했다. 모든 논문의 재현을 완료한 것은 아니다.
- **공개 저장소 5개**를 내려받아 코드 경로와 commit을 기록했다. Cisco Skill Scanner·MCP Scanner를 실행하고, CompoSkill은 **그래프 검색 부분만** 실행했다.
- Cisco Skill Scanner **2.1.0**은 `private` 읽기 Skill과 `webhook` 발행 Skill을 함께 검사할 때 `CROSS_SKILL_DATA_RELAY`를 보고했다. 두 Skill 각각의 finding은 0개였다. **기존 도구가 결합 위험을 전혀 못 본다는 주장은 틀린다.** [실행 근거](evidence/skill-scanner-results.json)
- MCP 도구 이름으로 기술한 읽기/발행 Skill 쌍과 단일 보고 Skill에서는 같은 오프라인 모드가 finding을 보고하지 않았다. **실제 침해를 재현한 결과가 아니라, 입력 표현과 분석 범위에 따른 차이**다.
- Cisco MCP Scanner **4.8.4**의 YARA 모드에서 일반 도구 2개는 무경고였다. 무해한 지시 덮어쓰기 문장도 표현에 따라 탐지 결과가 달랐다. LLM·API 분석기까지 실패했다고 확대 해석하면 안 된다. [실행 근거](evidence/mcp-scanner-results.json)

## 회의에서 제안할 범위

**우선 탐지 대상:** 비공개 자료를 읽고 요약·가공한 뒤 허용되지 않은 공개 대상에 보내는 경로. 읽기나 발행 기능 자체보다 **자료의 등급, 전달 경로, 대상의 접근 범위, 사용자 승인**의 조합을 검사한다.

**첫 구현:** 정적 수집 → 근거 있는 Skill/MCP 연결 → 데이터 흐름·권한 조건 검사 → 위험 후보/통제에 막힌 경로/근거 부족 구분 → 원문·경로·수정 제안 표시. 실제 실행 관찰은 통제된 평가 환경의 별도 단계다.

**차별성 검증 기준:** Cisco의 교차 Skill 검사, TFA 계열, 단순 권한 합집합 규칙보다 **같은 정상 업무를 덜 경고하면서 위험한 공개 전환을 더 정확히 구별하는가**. 통계적으로 개선되지 않으면 연구 기여 주장을 축소한다.
