# 2. 논문 비교 — 여섯 질문에 답하기

확인일: 2026-09-25. 아래 설명은 원문을 바탕으로 한 재서술이다. **저자 보고 수치와 이번 직접 실행 결과는 별개**다. arXiv만 확인한 연구는 게재 확정으로 표시하지 않는다.

## 핵심 결합 연구 5편

### R01. SkillProbe (2026-03-22)

[원문](https://arxiv.org/html/2603.21019v1) · §3.2–3.4 방법과 평가 부분 확인 · preprint

1. **무엇:** Skill 설명과 실제 동작의 불일치, Skill 간 위험 연결.
2. **원리:** Gatekeeper → Alignment Detector → Flow Simulator. 선언·구현 능력을 정규화하고, 출력 위험 태그와 후속 입력 위험 태그를 연결한다.
3. **방식:** 정적 코드/문서 분석 + LLM 의미 판단·흐름 시뮬레이션. 이름에 Simulator가 있다고 실제 OS 실행 추적으로 분류하지 않는다.
4. **취약점:** 숨은 기능, 과잉 권한, 데이터 전달을 통한 결합 위험.
5. **한계:** 태그와 규칙의 정확성에 의존. 시장 감사 결과가 실제 호스트에서의 공격 성공률과 같지 않다.
6. **우리 공백:** MCP의 실제 계정·대상 범위와 작업별 승인까지 결합할 때 추가 효과가 있는지 검증.

저자 평가: 2,500 Skill, 8 LLM 계열. “많이 다운로드되면 안전하다”는 판단을 반박하는 감사 결과이지 전체 시장의 침해율은 아니다. 공개 체험 서비스와 동명의 다른 GitHub/PyPI 도구를 혼동하지 않는다.

### R02. SkillReact — When Safe Skills Collide (2026-06, v1)

[원문](https://arxiv.org/html/2606.00448v1) · §II–V, VII–VIII 확인 · preprint

1. **무엇:** 개별 능력 정책을 통과한 Skill 쌍의 위험한 권한 합집합.
2. **원리:** 정규식으로 8개 능력을 추출하고 10개 금지 결합 패턴과 대조. LLM 보조·사람 판정으로 후보를 보정하고 도구 호출 시도도 평가한다.
3. **방식:** 정적 후보 생성 + 사람 보정 + 동적 도구 호출 평가.
4. **취약점:** 읽기+외부전송, 접근+실행 등 조합.
5. **한계:** 단순 능력 동시 존재는 실제 데이터 경로가 아니다. 추출 잡음·선택 편향·모델의 요청 수용 성향이 영향을 준다.
6. **우리 공백:** 입력·출력 계보와 수신 대상·작업 권한을 넣어 후보 과다를 줄이는지 비교.

1,520개 중 정책 통과 651개 → 211,575쌍. **22.25%는 구조적 후보율**이다. **18.2%는 경고된 pair-pattern membership에 대한 가중 유효율**이며 전체 쌍의 공격 성공률이 아니다. “22%가 실제로 해킹됨”이라고 발표하면 틀린다. 이 논문에는 설치 시 조합 검사까지 있으므로 그것만 새로 구현해 최초라고 할 수 없다.

### R03. SCR-Bench — Benign in Isolation, Harmful in Composition (2026-06-13)

[원문](https://arxiv.org/html/2606.15242v1) · 방법·결과·Appendix A 확인 · [코드](https://github.com/saint-viperx/SCR_Bench) 내부 확인 · preprint

1. **무엇:** 실행된 Skill 경로의 능력 전달, 신뢰 이전, 승인 혼동.
2. **원리:** SCR-CapFlow / TrustLift / AuthBlur로 나누고, 결합 조건과 분리 조건의 후속 상태를 비교한다.
3. **방식:** 동적 평가 벤치마크. 자체 탐지 제품과 구분한다.
4. **취약점:** 상류가 발견한 대상을 하류 변경 도구가 잘못 사용하거나 검토 결과를 승인처럼 취급.
5. **한계:** mock 부작용을 관측하는 통제 환경. 실제 레지스트리·호스트 정책·운영 잡음으로 일반화하는 데 한계가 있음을 저자도 명시한다.
6. **우리 공백:** Skill/MCP 혼합 경로와 실제 권한 조건을 유지한 대조군을 추가.

코드의 `experiment_case1.py`는 발견된 대상 ID와 `permissions.json`의 변경 대상이 같은지 검사한다. 단순 모델 답변보다 상태 검증이 강하다. 다만 조건별 프롬프트·대상도 달라지므로 구성요소 효과만 측정하려면 더 엄격한 동일 작업 대조가 필요하다. 이 연구의 수치를 이번에 재현하지 않았다.

### R04. SkillFuzz (2026-07-02)

[원문](https://arxiv.org/html/2607.02345v1) · §III–IV, 결과 개요 확인 · preprint

1. **무엇:** 선의의 Skill이 함께 활성화될 때 생기는 의도하지 않은 계획.
2. **원리:** Skill contract의 전제·후조건·상태 변경을 추출하고, contract 기반 탐색/MCTS로 조합을 선택. Skill 없는 계획과 비교한다.
3. **방식:** 도구 실행 없는 **모델 계획 탐색** + 일부 실행 검증. ‘실행 없음’을 ‘정규식 정적 검사’와 동일시하면 안 된다.
4. **취약점:** 읽기 업무가 불필요한 원자료 변경으로 확대되는 등 암묵적인 목적 이탈.
5. **한계:** 계획 차이는 피해 증거가 아니다. 모델·판정기·샘플 선택에 의존한다.
6. **우리 공백:** 계획에서 제안한 호출을 실제 MCP scope·데이터 계보에 결합해 실행 가능성과 위반 근거를 구분.

‘악성 문자열 없는 결합도 위험하다’는 근거다. 저자의 실행 검증 성공 비율은 선별한 높은 위험 후보의 수치이며 전체 시장 유병률로 바꿀 수 없다. 공개 구현은 이번 조사에서 확인·실행하지 않았다.

### R05. CompoSkill (2026-08-17)

[원문](https://arxiv.org/html/2608.16246v1) · §3–4 확인 · [코드](https://github.com/Limax666/CompoSkill) 내부 확인 · preprint

1. **무엇:** 개별 검사 통과 Skill들로 형성되는 다단계 공격 경로.
2. **원리:** 입력·출력 능력 겹침으로 Skill Composition Graph를 만들고 source–bridge–terminal 경로를 탐색. 공격자 지식에 따라 명시/암묵 유도를 구분한다.
3. **방식:** 메타데이터 그래프 + 의미 필터 + 동적 공격 평가.
4. **취약점:** 유출, 기억 변조, 권한 확대, 다중 에이전트 오염, 자원 소모.
5. **한계:** scanner-passing은 무결점 인증이 아니다. 추상 능력의 연결과 실제 인자·정책은 다르며 모델 판정도 포함된다.
6. **우리 공백:** 공격 경로 생성 자체보다 Skill×MCP의 구체적인 바인딩·권한·공개 대상 검증으로 범위를 좁힌다.

380개 작업 × 3변형 = 1,140 records. **최대 CFR 83.3%/80.6%는 경로 형성률이며 ASR가 아니다.** 코드는 고정 commit의 제한된 DFS 열거·점수 정렬이고 논문의 Yen식 탐색 설명과 그대로 같지 않다. 이번에는 합성 그래프 연결/단절만 실행했다. 논문 ASR 재현으로 소개하지 않는다.

## 논문 간 비교에서 얻는 판단

- **새롭지 않은 것:** 조합 위험, 능력 그래프, source/sink 경로, 설치 시 조합 검사, 문서-구현 정합성, 동적 상태 검증, 데이터 흐름 강제.
- **후보인 것:** 실제 MCP 바인딩과 권한·대상 정보를 가진 **혼합 워크플로의 정책 조건부 분석**, 근거 부족 표현, 환경 변경만으로 생기는 새 경로 비교.
- **아직 증명하지 못한 것:** 이 후보가 기존 TFA/상용 백엔드보다 우수하거나 학술적으로 독창적이라는 주장. 비교군과 분리 평가를 먼저 수행해야 한다.

논문에서 제시하는 ‘최초’ 표현은 저자의 주장이다. 조사자는 별도의 선행연구 검토 없이 그 표현을 프로젝트 홍보 문장으로 가져오지 않는다.
