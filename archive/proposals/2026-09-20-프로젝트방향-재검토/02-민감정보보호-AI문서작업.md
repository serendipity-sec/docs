# 후보 2 민감정보를 보호하는 AI 문서 작업

기록일: 2026-09-20 · 상태: 비교 후보 · 최종 채택 및 구현 착수 미정

## 사용자 관점의 출발점

“이 문서를 AI에게 맡기고 싶은데, 개인정보 때문에 못 올리겠어.”

회의록·신청서·상담 기록 등에서 유용한 요약이나 정리를 얻으면서, 외부 AI에 전달하는 민감정보를 확인하고 줄이는 상황을 다룬다. 최초 사용자군과 문서 종류는 아직 정하지 않았다.

김민우의 이번 반응:

> 2번은 PII 관련해서 중요한 관점이긴 한데 이미 많이 진행되었을거 같은 우려가 있고

개인정보 보호의 중요성에는 공감하지만, 기존 연구·제품과의 중복을 먼저 확인해야 하는 후보로 기록한다.

## 제품 가설

사용자는 원문과 실제 외부 전송 예정 내용을 비교하고, 업무에 필요한 정보가 남아 있는지 검토한 뒤 AI 작업을 요청한다. 서비스는 작업 결과와 전송 내역을 확인할 수 있게 한다.

입력은 문서와 작업 목적, 공개해도 되는 정보의 범위다. 결과는 가공된 문서, 실제 외부 전송 내용, 요약·정리 결과, 미확인 항목이다.

민감정보 보호를 약속하려면 원문을 처음 처리하는 위치부터 정해야 한다. 원문을 먼저 외부 모델로 보내 놓고 응답에서 개인정보를 가리는 방식으로는 이 가설을 충족할 수 없다. 브라우저·로컬 처리와 조직 내부 서버 처리 중 무엇을 선택할지는 미정이며, 각각의 신뢰 경계를 설명해야 한다.

## 발전시켜 볼 핵심

PII 탐지기를 새로 만드는 것만을 목표로 두지 않는다. 다음의 추가 가치가 실제로 필요한지 확인한다.

- 같은 사람이 여러 번 등장하는 문서에서 일관된 가명으로 치환해 맥락을 유지한다.
- 사용자가 외부로 나갈 내용을 확인하고 탐지 누락과 과도한 삭제를 수정한다.
- 단순 요약에 불필요한 정보와, 작업을 수행하는 데 필요한 정보를 구분한다.
- 문서와 대화 내역을 포함해 실제 전송되는 전체 요청을 추적한다.
- 원문·가공본·결과·로그의 보관 기간과 삭제 상태를 관리한다.

이는 차별화가 확인된 기능 목록이 아니라 검증할 방향이다. 가명 대응표를 보관하거나 결과를 원래 이름으로 복원한다면, 대응표 자체가 민감정보가 되므로 외부 전송·접근 제어·삭제를 따로 설계해야 한다.

이름·전화번호를 가렸어도 직장·직책·사건 설명의 조합으로 사람을 알아볼 수 있다. PII 탐지 성공과 익명성 보증을 같은 것으로 표현하지 않는다.

## 시연 후보

1. 합성 개인정보가 섞인 문서를 넣고 “업무별 할 일을 정리해 달라”고 요청한다.
2. 원문과 외부 전송 예정 내용을 나란히 보여 준다.
3. 탐지 누락이나 과도한 삭제를 사용자가 수정한다.
4. 확인한 가공본으로 AI 작업을 수행한다.
5. 실제 전송 기록에서 시험용 식별정보가 포함됐는지 확인하고 결과의 유용성도 평가한다.

원문이 브라우저, 서버, 외부 모델, 로그 중 어디에 있었는지 설명해야 한다. “검은 박스로 보인다”는 화면만으로 외부 전송이 차단됐다고 입증할 수 없다.

## 웹어플리케이션보안 산출물

웹서비스는 문서 업로드·전송 미리보기·사용자 수정·작업 실행·결과 조회·삭제 흐름을 제공한다. 데이터 흐름도에서 원문 보관 영역, 가공 영역, 외부 전송 영역, 결과 보관 영역을 구분한다.

설계·점검 대상은 문서별 인가, 업로드 처리, 임시 파일·로그의 정보 노출, 저장 보호, 외부 API 전송 경계, 삭제 처리, 가명 대응표 보호다. 브라우저에서 처리하는 경우에도 실제 네트워크 요청과 저장소 사용을 검사해야 한다.

최종 결과물 후보는 AI 문서 작업 웹서비스, 전송 근거 기록, 데이터 흐름·위협 모델, 자체 보안 점검 리포트, 개인정보 잔존과 업무 유용성을 함께 측정한 평가다.

## 기존 도구와 아직 모르는 것

[Microsoft Presidio](https://microsoft.github.io/presidio/)는 텍스트·이미지·구조화 데이터의 개인정보 탐지와 비식별화 기능을 설명한다. 확인일: 2026-09-20. 이번 세션에서는 설치·성능 평가를 하지 않았다. 후보 2는 기존 PII 도구·AI 보안 게이트웨이·문서 제품과의 상세 비교가 아직 필요하다.

아직 확인할 질문:

- 어느 사용자군이 어떤 문서를 처리하지 못해 실제로 불편한가?
- 기존 도구가 제공하는 전송 통제·가명화·복원·사용자 확인 기능은 어디까지인가?
- 한국어 문서나 특정 문서 양식에서 검증할 문제가 있는가? 한국어 지원 자체를 미확인 공백으로 단정하지 않는다.
- 삭제를 많이 해 요약이 무용해지는 문제와, 적게 해 정보가 남는 문제를 어떻게 평가하는가?
- 실제 민감자료 없이도 유효한 평가 자료와 과업을 마련할 수 있는가?

## 평가 제안

합성·허가된 자료에서 항목별 탐지 누락과 과잉 제거, 실제 외부 요청의 정보 잔존, 사용자의 수정 시간, 결과의 업무 정확도를 함께 측정한다. 치환되지 않은 문맥에 의한 식별 가능성도 별도 사례로 다룬다.

계속 발전시킬 근거는 특정 문서 작업에서 기존 방식보다 개인정보 노출을 줄이면서 유용한 결과를 얻는 증거다. 개인정보를 가리는 기존 도구에 일반적인 요약 화면만 붙이는 수준이면 재검토한다.
