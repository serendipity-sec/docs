# 지도교수 면담 — 개발 일정, 결과 평가 방식, 서비스 방향 논의

- **일시**: 2026-11-05(목) 14:26 (약 35분)
- **참석자**: 참석자 1~5 (녹취록 화자 구분만 있어 이름 미확인). 참석자 2는 발언 내용상 지도교수로 추정되며, 녹음은 박용준이 했음

## 안건별 논의 내용

### 1. 동적 검증 판정 기준에 관한 선행 연구 공유
참석자 1이 동적 검증 결과가 걸리면 사람이 직접 확인해서 실제 문제인지 판단하는 연구 논문 몇 편을 소개함. 판정 기준은 파일 접근, 네트워크 연결, 실행 여부이고, 가짜 자격증명을 써서 실제로 실행해 봄. 실행이 끝난 뒤 환경 상태를 보는 방법은 예를 들어 프롬프트에 심은 이메일 주소로 자격증명이 실제로 도착했는지 확인하는 방식이라고 설명함.

### 2. 개발 진행 상황과 일정
팀원 3명이 CCIT를 병행하고 있어 개발이 다소 늦어졌다고 공유함. 개발 완료 목표는 다음 주, 늦어도 다다음 주까지이며 바로 테스트에 들어갈 계획임. 테스트 단계의 역할 분담안: 일부는 테스트를 돌리고 기록, 일부는 기존 레포 리팩토링·구조 정리, 한 명은 워커 결과를 대시보드로 보여줄 프론트·백엔드 구현.

### 3. 검사 결과 표현 방식과 점수화
결과는 웹 보고서 형태로 보여줄 예정임. 어떤 변경이 실제로 문제가 됐는지, 어떤 검증 계획으로 확인했는지를 담음. 교수는 평가 요소별 가중치를 두고 "5점 만점에 4.2점"처럼 수치화할 수 있는지 검토하라고 요청함. 팀은 지금까지 점수화를 논의한 적이 없었고, 워크플로우와 변경 부분이 매번 달라 절대적인 수치는 어렵지만 고민해 보기로 함. 간단 보기와 상세 보기로 나누는 방안도 언급됨.

### 4. 검사 결과 저장 구조와 LLM 활용
실행 계획 등은 DB 테이블 하나에 속성 값으로 저장함. 실행 중 나오는 상세 로그는 RDB에 넣기 무거우면 별도 저장소(녹취상 "osql", 불명확)에 적재해 필요할 때 꺼내 쓸 예정임. 기존 도구가 맞지 않으면 AI로 구현하되, 앞서 공유한 판정 기준을 가져와 프로젝트에 맞게 수정할 계획임. 결과를 DB에 잘 저장해 두면 페이지 생성은 비교적 쉬우므로 워커 개발에 우선 집중하기로 함.

### 5. 검사 결과의 신뢰성 평가
교수가 우리 검사가 의미 있는 보고서를 내는지 평가 방법이 필요하다고 지적함. 다른 곳의 공개 데이터셋이나 다른 도구의 분석 결과가 있으면 우리 로직으로 돌려 비교하고, 무엇을 보완했는지 보여주는 방안이 나옴. 공개된 것이 없으면 정답지를 직접 만들어 기준을 잡기로 함. 소개된 논문은 n8n 대상이 아니라 일반 동적 검사 내용이어서 별도로 수정해 적용해야 함.

### 6. 서비스 방향 (교수 제안)
검사 결과를 매번 새로 돌리지 말고 축적해서, 다른 사람이 같은 검사를 반복하지 않게 해 주는 정보 서비스로 만들라는 제안. 구체적으로 나온 내용은 다음과 같음.
- 첫 화면에 그동안의 검사 이력, 최신 뉴스, 취약한 패키지 목록을 보여줌
- 일반 사용자에게는 간략한 점수, 관심 있는 사람·전문가에게는 상세 분석 보고서를 보여줌
- 사용하기로 하면 n8n으로 연결하는 바로가기 버튼을 둠
- 데모 때는 실시간 검사 과정과 누적 결과(예: "지난 일주일간 이만큼 검사함")를 함께 보여줌
- 축적된 데이터로 통계 분석

팀은 n8n 페이지로 이동시키는 링크는 쉽지만, 우리 서비스가 직접 호스팅해 실행하는 것은 별도 서버가 필요할 만큼 부담이 크다고 답함.

### 7. 취약 버전을 발견했을 때 대응
교수는 취약점을 찾았으면 고친 버전까지 제공하는 토탈 솔루션이 좋겠다고 제안함. 팀은 메이저 변경이 아니면 이전 패치 버전을 쓰도록 안내하는 편이 현실적이라는 의견이었고, 패치 제공은 추후 검토하기로 함.

### 8. 캡스톤 디자인 경진대회 출품
이번 주부터 다다음 주 사이에 출품 제출 요청이 올 예정이므로, 완성된 모습을 예상해서라도 제시해야 함. 참석자 5는 심사위원이 비전공자일 가능성을 고려해 "n8n 자동화를 안전하게 쓸 수 있도록 보안 검사와 사용 방법 안내를 제공하는 사이트"로 쉽게 설명하자고 제안함. 개발 중점은 보안 검사에 두기로 함. 교수는 마지막까지 검사 기능만 개발하다가 보여줄 것이 없는 프로젝트가 될 수 있다고 우려함.

### 9. 학사 일정 공지
- 19일 여승철 특강은 학생 의견에 따라 야간 온라인으로 진행할 가능성이 있음. 특강 전에 각 팀이 프로젝트 설명 1페이지를 미리 제출하고, 교수가 이를 전달하는 방식으로 하기로 함.
- 12월 둘째·셋째 주에 교수진의 중국 강의 일정이 있어, 프로젝트 발표를 일찍 진행할 예정임.

## 결정사항
- 개발은 다음 주, 늦어도 다다음 주 안에 완료하고 바로 테스트를 시작한다.
- 결과 페이지보다 워커(검사 실행·결과 DB 저장) 개발을 우선한다.
- 검사 결과의 신뢰성은 공개 데이터셋이나 다른 도구 결과와 비교해 평가하고, 공개된 것이 없으면 정답지를 직접 만든다.
- 특강 전에 프로젝트 설명 1페이지를 미리 제출한다.
