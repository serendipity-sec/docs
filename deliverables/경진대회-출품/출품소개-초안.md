# 캡스톤 디자인 경진대회 출품 소개 (초안)

## 작품명
**FlowDelta — n8n 업무 자동화를 고친 뒤에도 안전한지 확인해 주는 보안 검사 서비스**

팀 serendipity (김민우, 박용준, 양유상, 장준서) · 지도: 웹어플리케이션보안 캡스톤 2026-2

## 한 줄 소개
업무 자동화 워크플로를 수정하면, FlowDelta가 **고치기 전과 후를 같은 조건으로 실제로 실행**해서 새로 생긴 보안 문제를 찾아 웹으로 알려 줍니다.

## 왜 필요한가
- n8n 같은 업무 자동화 도구로 고객 응대, 주문 조회, AI 비서를 만드는 회사가 늘고 있습니다. 워크플로는 기능을 추가하면서 자주 바뀝니다.
- 작은 수정이 **남의 데이터를 보거나 지우는 문제**를 만들 수 있습니다.
  - 공개 프로젝트 n8n-claw의 "기억 삭제" 기능 추가에는 소유자 확인이 빠져 있었습니다.
  - 그 도구 코드를 따로 돌려 본 재현에서 다른 사용자의 기록이 지워졌습니다.
- 공개 검사 도구 5개로 이 수정의 전후를 검사했는데, 모두 위험한 버전과 고친 버전을 구별하지 못했습니다.

## 완성된 서비스의 모습

| 화면 | 사용자가 하는 일 | 상태 |
|---|---|---|
| 대시보드 | 등록된 워크플로의 최신 검사 결과를 한눈에 봄 | 디자인 완료, 구현 중 |
| 실행 상세 | 바뀐 부분 → 고른 시험 → 실행 기록 → 판정을 차례로 봄 | 디자인 완료, 구현 중 |
| 검증 히스토리 | 버전마다 결과가 어떻게 바뀌었는지 봄 | 디자인 완료, 구현 중 |
| 관리자 | GitHub 조직 로그인 뒤 검사 실행·결과 업로드 | 설계 완료, 구현 중 |

판정은 "위반 관측 / 위반 없음 / 판단 불가 / 지원 안 함"으로 나눕니다. 실행이 실패하거나 증거가 부족하면 안전하다고 표시하지 않습니다.

## 어떻게 동작하나
1. **변경 분석:** 전후 워크플로를 그래프로 비교해, 바뀐 노드가 어떤 데이터와 외부 동작까지 영향을 주는지 경로를 찾습니다.
2. **시나리오 선택:** 알려진 취약 사례 카드에서 이 변경과 맞는 시험을 고릅니다. 키워드 검색과 벡터 검색(pgvector)을 씁니다.
3. **격리 실행:** 같은 업무·같은 초기 데이터로 전후 버전을 각각 별도 n8n 컨테이너에서 실행합니다.
4. **독립 판정:** 워크플로 밖의 기록(서비스 이벤트, DB 변경 기록)으로 "누가, 누구의 데이터에, 무엇을 했는지" 확인합니다. 워크플로가 스스로 보고한 내용은 증거로 쓰지 않습니다.

## 시연 시나리오
1. 주문 조회 워크플로를 "위험하게 고친 버전"과 "제대로 고친 버전"으로 준비합니다.
2. 두 버전을 FlowDelta로 검사합니다.
3. 위험한 버전에서만 **다른 고객의 주문을 읽은 기록**이 잡히고, 웹 화면에 근거와 함께 표시됩니다.

## 기술 구성
n8n(Docker 격리 실행) · Python(FastAPI, SQLAlchemy) · PostgreSQL + pgvector · Semgrep(정적 검사) · GitHub OAuth · bubblewrap 샌드박스(업로드 처리)

## 지금까지의 결과 (11/12)
- 변경 분석, 시나리오 검색, 정적 검사, 결과 저장을 구현했습니다. 독립 판정기는 구현을 마치고 검토 중입니다.
- 합성 주문 조회 사례를 실제 n8n으로 전후 실행해 정상 업무 검사 24개를 통과했습니다.
- 보안 점검: 우리 시스템을 직접 공격한 20건 중 1건(낮음)을 찾아 고쳤고, 고친 뒤에는 20건 모두 막혔습니다.

## 기대 효과
- 워크플로를 배포하기 전에 "이번 수정으로 새로 위험해진 곳"을 근거와 함께 확인할 수 있습니다.
- 검사 결과가 쌓이면, 다른 사람이 같은 검사를 반복하지 않도록 정보 서비스로 쓸 수 있습니다.

## 한계
- n8n의 모든 노드를 지원하지 않습니다. 지원하지 않는 워크플로는 "지원 안 함"으로 표시합니다.
- 검사를 통과했다는 것은 그 조건에서 위반이 관측되지 않았다는 뜻이지, 완전히 안전하다는 증명은 아닙니다.
