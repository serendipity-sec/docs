# 프로젝트 방향 재검토와 추가 후보 3개

기록일: 2026-09-20 · 논의: 김민우와 AI 어시스턴트 · 상태: 개인 검토 및 팀 논의용

## 현재 결정

**(2026-09-20 갱신)** 1차 자료 검증([검증메모](검증메모-민우클로드.md)) 후 김민우는 **후보 1을 1순위**로 팀에 제안하기로 했다.
후보 2는 김민우의 직전 캡스톤(한국어 PII 가드레일, 2026-04)과 중복되어 접는다. 후보 3은 대안으로 남긴다.
팀 회의 안건은 [후보1-팀설득용-한장](후보1-팀설득용-한장.md). 코덱스 A·B·C 실험 후 컨셉을 발전시킨 [후보1-컨셉-v2](후보1-컨셉-v2.md) — "AI는 당신 머릿속의 규칙을 모른다"를 논지로, 규칙 선언 → 관계 테스트 → 수정 프롬프트·규칙 파일 → 재검증. **팀 합의·지도교수 승인 전이며 결정이 아니다.**

이전 상태: 후보 1·2·3을 모두 비교 후보에 올리고 각각 발전시켜 본다. 우선순위나 최종 주제는 정하지 않았다. 이번 기록은 팀 전체의 회의록이나 합의가 아니다. 9월 15일 회의에서 채택한 기존 AI 공급망 보안 주제를 폐기하거나 대체하기로 결정한 것도 아니다.

김민우는 구현 범위보다 **기존 도구와의 차별성, 실제 사용 이유, 사람들이 느끼는 공감과 인상적인 결과**를 더 고민하고 있다. 팀원들은 AI 분야에 관심이 있는 것으로 느껴지지만, AI가 필수 조건은 아니다. 괜찮은 주제가 있으면 빨리 착수하고 싶어 하는 분위기라는 개인 관찰이다.

## 이번 세션에서 바뀐 판단

1. 관련 사고와 시장 동향은 문제의 중요성을 뒷받침하지만, 우리 서비스의 필요성을 자동으로 입증하지 않는다.
2. 기존 문서의 “capability diff가 비어 있다”는 전제는 재검토해야 한다. SkilLock 공식 문서가 스킬의 명령·네트워크·파일 접근 변경 비교와 승인 이력을 설명한다. 실제 성능이나 완전성은 이번에 시험하지 않았다.
3. 예비 실험의 “11쌍 중 9쌍 놓침”은 보고서에 기록된 결과다. 현재 저장소에는 입력 쌍과 원본 출력이 없어 재검증하지 못했다. 기존 검사 결과가 변하지 않았다는 것만으로 우리 방식의 정확성·실용성이 증명되지는 않는다.
4. 과목 적합성만으로 웹서비스 권한 검증을 우선 추천했지만 김민우에게 와닿지 않았다. 이 후보를 계속 1순위로 밀지 않기로 논의가 바뀌었다.
5. 보안 도구 개발 외에, **보안 문제를 해결해야 사용할 수 있는 AI 웹서비스**도 주제 후보로 볼 수 있다.
6. 최종적으로 김민우가 세 후보 모두 발전시킬 가치가 있다고 판단해 기록을 요청했다.

## 다음 비교에서 확인할 것

각 후보는 같은 수준의 사용 시나리오와 간단한 시연을 준비한다. 한 후보만 정교하게 꾸며 나머지와 비교하지 않는다.

- 실제로 만날 수 있는 사용자는 누구이며, 최근 어떤 일을 하다 어려움을 겪었는가?
- 현재는 어떤 방법으로 해결하고 있으며, 무엇이 불편한가?
- 기존 도구를 그대로 쓰는 경우보다 구체적으로 무엇이 나아지는가?
- 사용자가 자신의 시험용 서비스·문서·작업을 제공해서 써보려 하는가?
- 한 번 신기하다고 느끼는 데 그치는가, 다음 작업에서도 다시 쓸 이유가 있는가?
- 기술 기여와 효과를 어떤 증거로 확인할 것인가?
- 웹어플리케이션보안 과목의 설계·구현·점검·배포·평가 산출물이 자연스럽게 이어지는가?

기존 과목 일정상 4주차 계획서가 예정되어 있으므로 비교 기간을 정할 필요는 있다. 그러나 이번 세션에서 새 마감일이나 담당자를 지정하지는 않았다.

## 근거와 읽는 법

아래는 2026-09-20 이번 세션에서 확인한 공식 공개 설명이다. 제품을 설치해 성능을 비교한 결과가 아니다.

- [SkilLock](https://github.com/skills-lock/skil-lock): capability 변경 비교, 정책, 승인 이력. 기존안과 직접 비교할 대상.
- [NVIDIA SkillSpector](https://github.com/NVIDIA/skillspector): 정적·선택적 LLM 분석 및 findings baseline 설명.
- [Cisco Skill Scanner](https://github.com/cisco-ai-defense/skill-scanner): 기존 스킬 분석 기능 확인.
- [Shannon](https://github.com/KeygraphHQ/shannon): 허가된 웹앱·API 대상 AI 보안 검증. 후보 1 비교 대상.
- [Presidio](https://microsoft.github.io/presidio/): 개인정보 탐지·비식별화. 후보 2 비교 대상 또는 기반 도구 후보.
- [LangChain Human-in-the-loop](https://github.com/langchain-ai/docs/blob/main/src/oss/langchain/human-in-the-loop.mdx): 도구 호출 승인·수정·거절. 후보 3의 기본 승인 기능과 비교.
- [Autorize](https://portswigger.net/bappstore/f9bbac8c4acf4aefa4d7dc92a991af2f): 다른 권한으로 요청을 재전송하는 기존 인가 검사 도구.
