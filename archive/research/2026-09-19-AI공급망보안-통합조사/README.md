## 핵심 내용

- 검사 단위는 특정 출처·버전의 구성요소와 이를 사용하는 호스트·권한의 조합이다.
- 선언된 기능, 정적으로 추정한 관계, 관찰된 동작, 실제 적용된 통제를 구분해 표현한다.
- 기존 검사 결과에 출처·참조·버전 변경·검사 누락의 근거를 연결하고, 팀의 도입 및 업데이트 검토를 지원하는 방향을 제안한다.
- 모델·앱 비교 실험은 원문 기준 구현 중이다. 탐지 정확도, 통제 효과, 기존 제품 대비 개선 효과는 확정된 성과가 아니다.

## 팀 검토에 활용하기

지원할 입력 형식과 호스트를 먼저 정하고, 정적 분석과 실행 관찰의 범위를 구분하는 데 활용한다. 이후 기존 검사기 연동 범위, 업데이트 검토 화면, 평가 표본과 지표를 논의할 수 있다. 본문에 제시된 일정과 범위는 제안이며, 실제 팀 일정·인원·결정 사항은 별도 계획서와 회의록을 기준으로 한다.

## 자료 범위와 근거

각 문서의 외부 출처 링크와 조사 기준일은 원문 그대로 유지했다. 이번 정리는 전달 자료의 보관과 탐색 구조 추가이며, 외부 출처의 재검증이나 실험 재실행을 수행한 결과가 아니다.

본문에서 언급하는 `repository-inventory.json`, `component-evidence.json`, 기타 JSON·JSONL과 실험 코드·예비 기록은 이번 전달 파일 4개에 포함되지 않아 이 폴더에 수록하지 않았다. 따라서 본문의 “같은 작업 폴더”는 최초 조사 환경을 가리키며, 이 저장소에 해당 근거 전체가 보관되어 있다는 의미가 아니다. 해시·요청·응답 단위의 검증에는 별도 근거 자료가 필요하다.
