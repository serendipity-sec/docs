## 📖 커밋 컨벤션이란

커밋 메시지를 같은 형식으로 쓰는 약속입니다. 형식이 통일되면 `git log`만 봐도 변경 이력이 읽히고, 나중에 변경 로그를 자동으로 만들거나 포트폴리오에서 내 기여를 보여주기도 쉽습니다.

## 🧱 구조 (Conventional Commits 기준)

```
<type>(<scope>): <subject>      ← 제목 (필수)
                                ← 빈 줄
<body>                          ← 무엇을, 왜 바꾸었는지 (선택)
                                ← 빈 줄
<footer>                        ← 이슈 번호, BREAKING CHANGE (선택)
```

- `scope`는 변경 범위입니다. 이 프로젝트라면 `agent`, `mcp`, `rag`, `splunk`, `ui` 처럼 모듈 단위로 정해 두면 좋습니다.

## 🏷️ 타입 목록

| 타입 | 의미 | 예시 |
| --- | --- | --- |
| `feat` | 새 기능 | `feat(mcp): CloudTrail 조회 도구 추가` |
| `fix` | 버그 수정 | `fix(parser): 빈 필드 예외 처리` |
| `docs` | 문서만 변경 | `docs: README 설치 방법 추가` |
| `style` | 포맷팅, 세미콜론 등 (동작 변화 없음) | `style: ruff format 적용` |
| `refactor` | 동작 변화 없는 코드 구조 개선 | `refactor(agent): 공통 베이스 클래스 분리` |
| `test` | 테스트 추가·수정 | `test(agent): 오탐 케이스 10건 추가` |
| `perf` | 성능 개선 | `perf(rag): 임베딩 배치 처리` |
| `chore` | 빌드·패키지·설정 등 기타 | `chore: pre-commit 설정 추가` |
| `ci` | CI 설정 변경 | `ci: GitHub Actions 테스트 워크플로 추가` |
| `revert` | 이전 커밋 되돌리기 | `revert: feat(mcp) 커밋 되돌림` |

## ✅ 작성 규칙

- 제목은 현재형·명령형으로, 끝에 마침표를 찍지 않습니다.
- 한 커밋에는 한 가지 변경만 담습니다. 제목에 "그리고"가 들어가면 쪼갤 신호입니다.
- 본문에는 코드를 보면 알 수 있는 "어떻게"보다 **"무엇을, 왜"**를 씁니다.
- 하위 호환이 깨지는 변경은 푸터에 `BREAKING CHANGE: 설명`을 남깁니다.

## 👀 좋은 예 vs 나쁜 예

**✅ 좋은 예**

```
feat(agent): L1 오탐 판별 신뢰도 점수 추가

신뢰도 0.8 미만은 사람 검토로 라우팅하기 위함.
사람 검토 부하를 줄이기 위한 P1 과제.

Refs #12
```

**❌ 나쁜 예**

```
수정
update
최종최종.py 업로드
이것저것 고침
```

- 😀 Gitmoji를 쓸 경우
    
    타입 대신 이모지로 변경 종류를 표현하는 방식입니다. 예: ✨ 새 기능, 🐛 버그 수정, 📝 문서, ♻️ 리팩터링. 눈에 잘 띄지만 도구 지원은 Conventional Commits가 더 넓습니다. `✨ feat(agent): ...`처럼 둘을 함께 쓰는 팀도 있습니다.
