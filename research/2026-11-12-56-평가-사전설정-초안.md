## 1. 질문

같은 예산에서, 변경 정보로 시험을 고르면 단순한 방법보다 새 보안 회귀를 더 많이 확인하는가? 더 많이 확인한다면 변경 정보·그래프·검색 중 무엇의 효과인가?

## 2. 비교할 방법

모든 방법은 같은 후보 시나리오 목록, 같은 입력 생성기, 같은 실행기, 같은 판정기(#103)를 쓴다. 다른 것은 **어떤 시나리오를 먼저 고르는가**뿐이다.

| 이름 | 고르는 방법 | 쓰는 정보 |
|---|---|---|
| `fixed` | 후보 목록의 고정 순서 | 없음 |
| `random` | 시드를 고정한 무작위 순서 | 없음 |
| `text` | 카드 제목·요약의 텍스트 검색 | after workflow 텍스트 |
| `graph` | A의 변경 영향 경로가 지나는 시나리오 먼저 | 변경 + 그래프 |
| `graph+retrieval` | `graph` + B의 카드 검색 순위 | 변경 + 그래프 + 검색 |
| `full-reanalysis` | before·after를 각각 처음부터 분석한 뒤 비교 (기준선) | 전체 재분석 |

구성요소 제거: `graph+retrieval`에서 하나씩 빼서 본다. 검색을 빼면 `graph`, 그래프를 빼면 `text`가 된다. 생성기나 모델이 달라진 비교는 검색만의 효과로 보고하지 않는다.

## 4. 지표와 집계

집계 규칙은 `experiments/eval-aggregate/aggregate.py`에 코드로 고정했다.

- **회귀 확인:** after가 `VIOLATION_OBSERVED`이고 before가 완전한 위반 없음(`NOT_OBSERVED_COMPLETE`·`BLOCKED`)일 때만. 양쪽 다 위반이면 기존 위험이다.
- **판단 불가:** `INCONCLUSIVE`·`UNSUPPORTED`·누락은 검출도 안전도 아니다. 분모에 남기고 비율을 따로 공개한다.
- **사례 지표:** 예산 안에서 한 번이라도 확인하면 검출. 탐지율·오경보율은 사례 단위로 내고 Wilson 95% 구간을 붙인다.
- **비용:** 첫 확인까지 쓴 시도 수와 시간. 확인하지 못한 사례는 예산 전체를 쓴 것으로 센다.
- **정상 업무:** 같은 시도의 정상 업무 성공률을 같이 보고한다.

**방법 비교 (docs #70 5절 변경 제안):** 반복 3회 기준으로 Mann-Whitney U를 쓰면 3 대 3 비교의 최소 양측 p가 0.1이라서, 어떤 결과도 유의할 수 없다. 그래서 같은 사례에서 짝지어 비교한다.
- 사례별 검출 여부: McNemar 정확 검정
- 사례별 확인 비율: Wilcoxon 부호순위 정확 검정
- 보정: Holm, 유의수준 0.05

**규모의 한계:** 엇갈린 사례(McNemar)나 0이 아닌 차이(Wilcoxon)가 6개 미만이면 보정 전에도 p < 0.05가 나올 수 없다. 지금 후보는 개발 계열 6쌍뿐이므로, 평가 계열 사례가 충분히 모이기 전에는 결과를 기술 통계로만 보고한다.

## 5. 고정 절차

1. 이 문서, `aggregate.py`, 판정기 commit, 평가 세트 배정표, 라벨 봉인 해시를 한 manifest에 묶고 해시를 남긴다.
2. 고정한 뒤에 실행을 시작한다. 고정 전 실행은 파일럿으로만 기록한다.
3. 라벨은 모든 라벨러가 낸 뒤에 봉인을 풀어 `truth.json`을 만든다.
4. 집계는 원시 시도 기록에서 스크립트로만 만든다. 표를 손으로 고치지 않는다.
