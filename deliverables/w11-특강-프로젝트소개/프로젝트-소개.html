n8n은 앱을 연결해 일을 자동화합니다. FlowDelta는 업데이트 전후에 같은 일을 시켜, 새 버전이 권한 밖의 데이터를 읽거나 바꾸는지 확인합니다.

해설과 출처

워크플로우란

요청을 받아 일을 끝낼 때까지 어떤 단계를 어떤 순서로 실행할지 연결한 절차입니다. n8n은 각 단계를 노드라고 부릅니다. AI를 붙이면 모델의 판단에 따라 호출하는 도구와 그 도구에 전달하는 값이 달라질 수 있습니다.

그림을 읽는 법

이전 버전에는 요청자 자신의 자료로 가는 연결이 있습니다. 업데이트 후에는 다른 사람의 자료로 가는 경로가 추가됐습니다. 이 점선은 확인할 후보입니다. 실제로 권한 밖의 자료를 읽었는지는 실행 증거로 판정합니다.

업무의 성공과 권한의 준수

왜 업데이트에 집중했나

첫 회의에서 팀은 외부 스킬과 MCP 서버처럼 AI에 연결하는 구성요소의 공급망 보안 사고에 주목했습니다. 남이 만든 기능이 바뀌면 그 변경도 업무에 들어옵니다. 그래서 어떤 워크플로우 변경이 기존 데이터·권한과 결합할 때 문제가 생기는지 조사하기로 했습니다.

개발자는 바뀐 위치와 다시 할 시험을 찾아 수정할 수 있습니다. 도입 담당자는 같은 워크플로우의 여러 버전에 대해 무엇을 검사했고 어디까지 확인했는지 비교합니다. 공개 화면으로 정제된 결과를 공유하고 관리자가 등록·검사를 요청하는 방향입니다.

검사 대상

비교 단위는 같은 업무를 수행하는 n8n 워크플로우의 기준 버전과 도입 후보 버전입니다. 현재 워크플로우 변경 경로는 정책, 의존성, 모델과 환경 설정을 고정합니다. 각 버전에 같은 시작 상태의 별도 사본을 줍니다.

어떤 변경에 결과를 연결하나

두 버전에 여러 수정이 함께 들어갔다면 처음에는 그 변경 묶음에 결과를 연결합니다. 한 연결이 원인이었다고 좁히려면 해당 변경을 분리한 추가 비교가 필요합니다. 실행한 파일과 조건을 다시 찾을 수 있도록 참조와 해시를 남깁니다.

검사 아키텍처

바뀐 연결을 따라
필요한 시험을 고릅니다.

A가 영향을 받을 경로를 찾고, B가 시험을 골라 C에 넘깁니다. 판정기는 C의 기록에 업무 규칙을 적용합니다.

해설과 출처

입력에서 실행까지

  • 입력. 업무와 정책, 두 버전과 환경을 고정하고 원본을 추적할 수 있는 스냅샷을 만듭니다.
  • A · 분석. 노드를 연결한 그래프에서 실행 순서와 데이터 이동을 따라갑니다. 변경 위치, 영향을 받을 수 있는 경로, 정적으로 분석할 수 있었던 범위를 남깁니다.
  • B · 계획. 변경 경로와 정책을 바탕으로 시나리오 카드를 검색합니다. 카드는 시험이 적용되는 조건과 필요한 증거를 담습니다. 검색한 카드를 모델에 함께 주는 RAG 방식을 설계했고, 모델이 제안한 후보도 등록된 시험 목록과 허용 조건에 맞춰 확인합니다.
  • C · 실행. 등록된 정적 검사는 구성상의 경고를 남깁니다. 지원하는 동적 시험은 전용 n8n 환경과 합성 서비스에서 두 버전을 실행하고 응답, 서비스 이벤트, 데이터의 전후 상태를 수집합니다.

판정과 공개

검사 대상과 별도로 남긴 기록에 판정기가 미리 정한 정책을 적용합니다. 각 판정을 원본 변경·계획·실행과 연결하고 공개용 결과만 포털에 전달합니다. 포털에서 검사 요청을 대기열에 넣고 워커가 처리하는 방식은 서비스 설계에 포함돼 있습니다.

  • C · 등록 실행과 산출물 연결 · 정적 검사

증거와 판정

새로 생긴 위반인지
어떻게 알 수 있을까?

응답이 성공해도 권한을 넘었을 수 있습니다. 두 버전의 서비스 기록과 실제 데이터 변화를 같은 업무 규칙에 대조합니다.

해설과 출처

한 번의 실행에서 읽을 수 있는 결과

위반 관측은 금지된 효과가 실제로 발생했다는 독립 기록이 있을 때입니다. 차단 관측은 보호 조건이 금지 동작을 거절한 증거가 있을 때입니다. 위반 미관측은 필요한 관측을 마쳤고 시험 범위 안에서 위반이 발견되지 않았을 때입니다. 판단 불가는 필요한 증거가 없거나 그 기록을 해당 실행에 연결할 수 없을 때입니다.

두 버전을 함께 읽기

이전에는 차단됐거나 완전한 관측에서 위반이 없었고 후보에서 위반이 관측되면 그 시험의 보안 회귀입니다. 양쪽에 위반이 있으면 기존 문제입니다. 수정 후에는 금지 동작이 차단됐는지와 정상 업무가 계속 되는지를 각각 검사합니다. 증거가 빠진 쪽이 있으면 새 위반 여부는 판단할 수 없습니다.

기존 도구와 차이

이 변경이 우리 업무의 규칙을 어겼을까?

FlowDelta는 변경에 맞는 시험을 골라 업무 규칙 위반을 확인합니다. 같은 시험 횟수에서 새 위반을 더 잘 찾는지는 평가할 과제입니다.

해설과 출처

비교의 기준

n8n의 템플릿 라이브러리는 업무에 쓸 자동화를 찾게 해줍니다. 버전 이력은 이전 구성을 열고 복원하게 해주며, Security Audit은 자격 증명·노드·인스턴스 등에서 흔한 구성 문제를 점검합니다.

0xCD4의 공개 도구는 내보낸 워크플로우를 정적으로 검사하고 위험 경로와 변경을 보여줍니다. 팀이 확인한 버전은 지원하는 HTTP 동작에 대해 격리된 전후 실행도 제공합니다.

무엇을 검증할 계획인가

FlowDelta의 가설은 변경 경로와 근거 카드를 바탕으로 시험을 고르면 같은 예산에서 회귀를 더 잘 찾는다는 것입니다. 고정 순서나 단순 검색을 쓰는 경우와 동일한 조건에서 비교할 예정입니다.

해설과 출처

관측한 효과

기억 삭제 기능이 추가된 워크플로우에서 A는 도구와 에이전트의 연결 변화를 표시했습니다. 별도의 연구 실험에서는 선택한 도구 코드를 합성 환경에서 재생했고, 일반 사용자의 요청으로 다른 사용자의 가상 기억이 사라지는 상태 변화를 관측했습니다. 소유권 검사를 보완한 버전에서는 같은 동작이 차단됐습니다.

어디까지 확인했나

비교 대상은 고정한 도구 버전과 합성 수신부입니다. 전체 에이전트가 실제 모델을 통해 이 도구에 도달하는 경로는 별도로 확인해야 합니다. 팀이 고정한 공개 정적 검사 도구 다섯 개는 조사한 취약·보완 버전 쌍을 구분하지 못했습니다. 이 한 사례의 결과로 일반 탐지 성능을 추정할 수는 없습니다.
