# serendipity · docs

웹어플리케이션보안(캡스톤디자인) 2026-2학기 팀 **serendipity** 의 문서 저장소입니다.
회의록·제출물·조사 자료를 보관하며, 구현 코드는 [`platform`](https://github.com/serendipity-sec/platform) 저장소에 있습니다.

## 프로젝트

**FlowDelta — AI 워크플로우 변경의 보안 회귀 분석과 실행 검증**
전후 구성·환경·의존성을 업무·정책과 함께 비교하고, 변경된 위험을 독립 실행 증거로 확인하는 도구를 설계한다.
연구 평가를 우선하는 재사용 가능한 오픈소스 코어가 목표다. 설계·구현 준비·연구 성능의 완료 범위를 구분해 기록한다.

**최근 주간 보고:** [2026.10.15 교수님 설명용 HTML과 제작·검증 방법](deliverables/weekly/2026-10-15/README.md) — 정상 주문 통합 실적, 역할별 전달 흐름, 10월 22일 목표와 전체 계획. 아래 준비 상태 문서는 이전 준비 단계 기록이며, 해당 주간 실적은 이 보고서의 기준일과 근거를 확인합니다.

**중간발표 자료:** [FlowDelta 18쪽 PDF와 자료 안내](deliverables/w09-중간발표/README.md) — 2026-10-22 자료 원본, 2026-10-23 저장소 업로드.

### 팀원이 읽을 순서

| 순서 | 문서 | 확인할 내용 |
|---|---|---|
| 1 | **[현재 준비 상태](plans/current-readiness.md)** | 이미 구현한 것, 실제 확인 범위, 아직 남은 구현 |
| 2 | **[전체 설계](final/README.md)** | 무엇을 만들고 업무·정책·전후 입력을 어떻게 다루는지 |
| 3 | **[개발 상세 설계](plans/implementation-design.md)** | Python 구성, 모듈 구조, 현재 계약과 후속 확장 계획 |
| 4 | **[팀 구현 계획](plans/team-implementation.md#current-start)** | 네 구현 영역, 수정할 폴더·함수, 예제와 완료 조건 |
| 5 | **[platform 코드·실행 안내](https://github.com/serendipity-sec/platform)** | 설치·실행·Schema·예제·테스트 |

**공유 상태:** 설계·계획·진행 설명은 이 저장소의 `main`, 실행 가능한 코드·Schema·예제는 `platform`이 기준이다.
입력·공통 기반과 두 정상 사례는 준비 PR에서 확인됐으며, `platform/main` 반영에는 팀원 리뷰 승인이 남아 있다.
A/B/C의 실제 모듈 연결과 최종 연구 성능은 아직 완료된 결과가 아니다. [코드 기준과 근거](plans/current-readiness.md)를 확인한다.

입력·데이터 기준, 평가 계획, 조사 근거는 [전체 설계](final/README.md)에서 이어 읽는다.
[팀 Notion 최종 설계](https://app.notion.com/p/3eec2d6e1537801bb949de84023a2f23)는 별도 공유 화면이며, 이번 Git 정리에서 Notion 원문은 변경하지 않았다.
한 비교에서는 업무·정책·초기 상태를 통제하고, 공개 템플릿·합성 변형·실제 운영 이력을 구별한다.

아래는 기존 팀 운영 기록이다. 모듈별 구현 역할과 현재 착수 기준은 위 팀 구현 계획에서 확인한다.
