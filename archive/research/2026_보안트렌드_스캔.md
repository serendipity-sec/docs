# 2026 보안 트렌드 스캔 — 우리 주제는 어디에 있는가

조사일 2026-09-19 · 조사자 김민우 · 국내 기관·언론 + 글로벌 + 학술 논문

> **한 줄 결론**: 2026년 국내외 보안 트렌드의 한가운데에 "AI 에이전트 공급망"이 있고,
> 그중에서도 **"에이전트가 읽는 설정·지침이 곧 공급망"** 이라는 인식이 올해 2월(Check Point)과
> 9월(Red Hat 논문)에 학계·업계 양쪽에서 확정됐다. 우리 주제는 트렌드에 맞는 정도가 아니라
> **정확히 그 자리**에 있다. 다만 9월 7일자 Red Hat 논문이 같은 표면을 측정했으므로,
> 그것과 무엇이 다른지를 이제 명확히 말할 수 있어야 한다 (§6).

교수님 상담에서 "국내 기관도 이 문제를 보고 있는가"에 답하는 자료다. 전부 공식 발표다.

**읽는 법** — 금융보안원이 1년 3개월 전에 이미 "MCP 도구 오염 = 공급망"이라고 못 박았다.
국정원은 에이전틱 AI를 별도 항목으로 뺐다. 범부처 대책은 SBOM을 의무화하는데,
**SBOM은 패키지 목록이지 스킬·규칙 파일을 담는 형식이 아니다** — 한남대 이만희 교수가 보안뉴스에서
"AI BOM 필요성"을 언급한 이유가 이것이다. 우리 프로젝트의 "출처·해시·검토 이력" 기록은
사실상 스킬·규칙 파일용 BOM이다. **이 연결을 계획서에 쓰면 국내 정책 흐름 위에 올라탄다.**

## 4. 새로 찾은 사례 — 기존 사례집에 없던 것

[실제사례와_통계.md](실제사례와_통계.md)에 없던 것만. 타임라인에는 오늘 추가했다.

### 4-1. ★ Check Point — Claude Code 프로젝트 파일 RCE (2026-02-25 공개)

**우리 매트릭스의 "규칙 파일" 행에 드디어 실제 사고 사례가 생겼다.**

| CVE | 벡터 | 동작 |
|---|---|---|
| **CVE-2025-59536** | `.claude/settings.json` 의 hooks | `SessionStart` 훅이 시작 시 **경고 없이** 셸 명령 실행 |
| **CVE-2026-21852** | `.claude/settings.json` 의 `enableAllProjectMcpServers` | MCP 서버를 **자동 승인**, 초기화 명령이 **신뢰 대화상자를 읽기도 전에** 실행 |
| (미부여) | `ANTHROPIC_BASE_URL` 환경변수 | API 트래픽을 공격자 서버로 → **API 키 평문 유출**, 신뢰 확인 전 |

- 공격 조건: **악성 저장소를 클론하고 여는 것만으로** 성립
- 보고 2025-07-21 → 최종 수정 2025-12-28 → 공개 2026-02-25. Anthropic 협력 패치 완료
- **의미**: "규칙·설정 파일은 코드가 아니라 안전하다"는 가정이 실증적으로 깨졌다.
  파일 하나가 hooks(실행) + MCP(도구) + env(네트워크)를 한꺼번에 연다 — **한 파일 안에서의 조합**.

### 4-2. ★ Snyk — ClawHub 283개 "유출 스킬" (2026-02-05)

| 항목 | 값 |
|---|---|
| 검사 | ClawHub 전체 **3,984개** 스킬 (Evo Agent Security Analyzer) |
| 결과 | **283개(7.1%)** 가 자격증명을 노출 |
| 성격 | **악성이 아니다.** `moltyverse-email`, `youtube-data` 같은 정상·인기 스킬 |
| 원인 | SKILL.md 지침이 "API 키를 메모리에 저장하라", "키가 포함된 URL을 사용자에게 공유하라", "curl 명령에 키를 넣어라" — **에이전트를 로컬 스크립트처럼 취급**, 모든 데이터가 LLM 컨텍스트·로그를 지난다는 걸 잊음 |
| 노출 | API 키·토큰, **신용카드 번호**, PII, 로그인 정보 |

- **의미**: 악성(ClawHavoc) vs **부주의(leaky)** 는 다른 문제다. 스캐너의 악성 판정과 별개로
  **"이 지침이 자격증명을 어디로 흘리는가"** 는 capability 질문이다. OWASP AST03·AST04에 해당.
- Snyk 권고 첫 줄이 `mcp-scan --skills` — 즉 **기존 도구로 잡히는 종류**임을 인정. 우리 기여는 탐지가 아니라 근거 제시.

### 4-5. Deadbugz — 시간 지연 MCP 서버 (2026-09, Pillar Security)

한 계정이 **74분 만에 무관한 AI·개발 도구 프로젝트 23곳에 PR**. 서버는 텍스트 포맷·요약이라는
무해한 도구 2개를 제공하다가 **정확히 3번째 도구 호출 이후** 메타데이터를 SSH 키·AWS 자격증명·

- **의미**: 버전이 바뀌지 않아도 **런타임에 동작이 바뀐다.** 정적 capability diff의 명시적 한계 —

### 4-6. Microsoft — 오염된 MCP 도구 설명 (2026-06-30)

## 5. ★ 학술 — 2026년 9월 7일자 논문이 우리 표면을 측정했다

### Scanning the Harness (Kapner et al., Red Hat + Ben-Gurion Univ., arXiv 2609.07360)

이 논문은 **읽어야 한다.** 우리와 같은 표면을 가장 엄격한 방법으로 측정했다.

**그들이 정의한 것** — "harness" = 에이전트를 구성하는 지속 아티팩트: 지침 파일·스킬·명령·hooks·
MCP 선언·서브에이전트. **"harness는 의존성 계층이다. 마켓과 공개 저장소에서 설치되고, 개발자
권한으로 실행되고, 세션을 넘어 지속되는데, lockfile도 설치 시 검사도 *구성요소가 무엇을 해도
되는지에 대한 어휘*도 없다."** — 우리 제안서 15장과 같은 문장이다.

**측정** — GitHub 공개 저장소 **3,171개** (다중 구성요소 셋업 2,660 + 스킬 컬렉션 511).
규칙 31개, 전부 결정론적(모델 호출 없음). 3단 검증: 독립 재구현 → LLM 판정(프롬프트 공개) →
별도 모델 세션 재검토. **사람 채점은 없음**을 명시.

| 결과 | 비율 |
|---|---|
| 보안 결함 있는 셋업 | **16.0%** |
| MCP 서버 버전 미고정 (`npx -y @scope/server`) | **9.8%** |
| `Bash(python:*)` 처럼 좁아 보이지만 임의 실행 사전 승인 | 3.1% |
| 셸을 사전 승인하는 스킬 (설치하는 모든 저장소에 전파) | 3.8% (컬렉션의 3.7%) |
| 둘 이상 어시스턴트 동시 설정 — **지침 파일 간 일치를 보장하는 것 없음** | 17.5% |
| 원 도구 탐지율 25.5% → 검증 후 18.4% | 오탐 7.1%p |

인용된 선행 연구: 두 마켓 31,132개 스킬 중 **26.1%가 취약 패턴** [3].

**공개된 것** — 도구 `harness-eval` (Python, Claude Code·Cursor·Copilot·Gemini CLI·OpenCode·
Windsurf·Cline·Codex 형식 탐지, SARIF 출력) https://github.com/redhat-community-ai-tools/harness-eval
+ 코퍼스 매니페스트(저장소·고정 커밋)·판정 전부 https://github.com/Benkapner/harness-eval-experiments

### 그들이 하지 않은 것 — 우리 자리

| 논문이 명시한 한계 | 우리 |
|---|---|
| **"살아남은 모든 규칙은 파일 하나와 그 주변 트리만 읽는다"** — 단일 스냅샷 | **두 버전 비교** (capability diff) |
| 두 파일을 비교하는 규칙은 "차이가 대개 의도된 것"이라 **관찰로만 보고** | 의도 여부를 사람이 판단하도록 **근거를 나란히** |
| `capability` 라는 단어가 **논문 전체에 0회** — 알려진 나쁜 설정 패턴 매칭 | "무엇을 할 수 있게 됐나"의 차집합 |
| **지침 파일만 있는 저장소 1,633개 제외** — "그 파일을 읽는 규칙이 없다" | CLAUDE.md·AGENTS.md **내용**이 검사 대상 |
| "자격증명 유출 경로는 확인된 인스턴스 없음" | Snyk 283건과 결합해 설명 가능 |
| 사람 채점 없음 | 검토 기록 = 사람 판단 축적 |

**결론**: 논문은 우리 문제를 **입증**했고 우리 방법을 **하지 않았다.** 게다가 3,171개 저장소의
고정 커밋 매니페스트를 공개했으므로, ClawHub 데이터셋(스킬)에 이어 **설정 파일용 평가 코퍼스**가
하나 더 생겼다. 우리 capability diff 실험(round 3)의 "실제 저장소 쌍" 표본을 여기서 뽑을 수 있다.

### 같이 볼 논문 — Maloyan & Namiot (arXiv 2601.17548, 2026-01-24)

에이전트 코딩 어시스턴트 대상 프롬프트 인젝션의 **체계적 분석**. 78개 연구 메타분석, 42개 공격 기법,
3차원 분류(전달 벡터 × 공격 양상 × 전파). 적응형 공격 성공률 **85% 초과**, 방어 18종 대부분
**완화율 50% 미만**. → "정적 검사로 막는다"가 아니라 "사람이 볼 근거를 준다"는 우리 프레임의 근거.

## 6. 트렌드 키워드 ↔ 우리 주제 매핑 — "주제에 맞는 주제"

조사 전체에서 반복된 키워드를 우리 4개 검사 대상 계층(②③⑥⑪)에 대응시켰다.

| 트렌드 키워드 | 누가 말했나 | 우리 기능 | 강도 |
|---|---|---|---|
| **설정·지침 = 공급망** | Check Point(2월), Red Hat(9월), 금보원(도구 오염), 보안뉴스(AI BOM) | 규칙·스킬·MCP 설정 검사 | ★★★ |
| **lockfile 없음 / 버전 미고정** | Red Hat 9.8%, postmark-mcp, 금보원 | 출처·해시·버전 기록 | ★★★ |
| **승인 이후 변화** (update drift) | OWASP AST07, CVE-2025-54136, Deadbugz | **capability diff** | ★★★ |
| **가시성 부족** | Akto 21%, 바이라인 ③, Gartner #1 | 관계 그래프 + 검토 기록 | ★★ |
| **악성 vs 부주의** | Snyk 283(부주의) vs ClawHavoc(악성) | 판정이 아닌 근거 제시 | ★★ |
| 에이전트 IAM / 권한 어휘 | Gartner #4, Red Hat "어휘 없음" | capability 목록 = 권한 어휘의 씨앗 | ★★ |
| 런타임 행위 변화 | Deadbugz, Microsoft 도구 설명 | **우리 범위 밖** — 정직하게 명시 | 경계 |
| 노출 인프라 | SecurityScorecard 40,214 | **우리 범위 밖** | 경계 |

### 주제 문장 후보 3개 (초안·계획서용)

트렌드 언어로 다시 쓴 것. 팀에서 하나 고르거나 섞으면 된다.

**A. 공급망 언어** (국내 정책 흐름에 올라탐)
> "SBOM이 담지 못하는 AI 에이전트 설정·지침 계층의 출처·버전·변경을 기록하고, 승인 이후 무엇을
> 할 수 있게 바뀌었는지를 근거와 함께 보여 주는 검토 지원 플랫폼"

**B. 드리프트 언어** (OWASP AST07 직결, 실험 결과와 정합)
> "AI 코딩 에이전트 구성요소의 버전 간 capability 변화를 찾아내고, 스캐너마다 갈리는 판정의
> 근거를 나란히 놓아 사람이 결정하게 하는 웹 플랫폼"

**C. 거버넌스 언어** (Gartner·바이라인 ④·Akto와 정합)
> "팀이 도입하는 스킬·MCP·규칙 파일에 대해 '누가 어느 버전을 검토했고 그 뒤 무엇이 바뀌었는가'를
> 답할 수 있게 하는 에이전트 구성 거버넌스 도구"

추천은 **B를 본문, A를 배경 설명**으로. B가 실험(11쌍 중 9쌍)과 논문(Red Hat이 안 한 것)에
바로 연결되고, A는 "왜 지금 한국에서"에 답한다. C는 범위가 넓어 보일 위험이 있다.
