# 자료 선정과 조사 기록

확인일: **2026-09-21** · 초기 자료 선정에서는 읽기 전용 공식 저장소·웹 문서·데이터 카드를 확인했고 전체 데이터셋은 다운로드하지 않았다. 이후 직접 작성한 합성 fixture에 고정 버전 스캐너를 설치·실행했으며 결과는 [실제 AI 행동 실행 결과와 질문 3·4의 현재 답](05-실제-AI행동-실행결과.md)에 기록했다.

## 1. 선정 결론

**공개 자료는 입력 연결과 기존 기능 확인에 재사용하고, 승인 시간선·실효 권한·검사 불완전성은 자체 자료로 만든다.** 조사한 공개 자료 중 이 세 조건과 정상 대조군을 함께 제공하는 완성된 데모 묶음은 확인하지 못했다. 그런 자료가 전혀 존재하지 않는다고 결론 내리지는 않는다.

|---|---|---|
| Cisco Skill Scanner evals | 정상·위험 입력이 제대로 스캔되는지 사전 점검 | 우선 사용 후보 |

## 2. 확인한 원문

### S01. Cisco Skill Scanner 평가 자료

현재 main 확인 커밋: `431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8`.

공식 평가 README는 `evals/skills`의 schema-v2 사례 24개와 `evals/test_skills`의 legacy smoke 3개를 구분한다. 전자는 자체 기대값·파일 해시·라벨 근거를 포함한다. 작은 시작 집합은 `safe-skills/simple-math`, `data-exfiltration/config-tunnel-exfil`이다. 이후 `prompt-injection/jailbreak-override`, `behavioral-analysis/multi-file-exfiltration`을 더할 수 있다.

확인한 기대값은 `human_reviewed`, `scanner_independent:true`를 선언한다. 이는 제작자의 라벨 설명이며 우리 독립 재심사 결과가 아니다. 도구 개발에 쓰인 공개 회귀 자료이므로 해당 도구와 경쟁 도구의 공정한 독립 순위 평가셋으로 삼지 않는다. 이름에 behavioral이 있어도 실제 런타임 평가라고 가정하지 않는다.

출처: [평가 README](https://github.com/cisco-ai-defense/skill-scanner/blob/431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8/evals/README.md), [정상 사례 기대값](https://github.com/cisco-ai-defense/skill-scanner/blob/431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8/evals/skills/safe-skills/simple-math/_expected.json), [위험 사례 기대값](https://github.com/cisco-ai-defense/skill-scanner/blob/431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8/evals/skills/data-exfiltration/config-tunnel-exfil/_expected.json), [LICENSE](https://github.com/cisco-ai-defense/skill-scanner/blob/431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8/LICENSE).

재사용: 저장소 LICENSE와 확인한 사례는 Apache-2.0 표기. 실제 도입 시 선택 파일의 별도 고지·NOTICE·변경 사항도 확인하고 기록한다. 이번 문서에는 제3자 사례 원문을 복사하지 않았다.

### S02. Cisco MCP Scanner 오프라인 입력

현재 main 확인 커밋: `9e47aabdf2017b82e78f3419f39a75f20b6f98fa`.

`static` 모드는 미리 만든 `tools`, `prompts`, `resources` JSON을 분석한다. 파일 형식은 tools 배열 안에 `name`, `description`, `inputSchema`를 두는 형태다. YARA만 사용하면 live MCP 서버 없이 검사하는 경로를 구성할 수 있다. 서버 구현이나 실제 접근 권한을 검증하는 모드는 아니다.

readiness의 `good_tool.json`과 `bad_tool.json`은 명세 품질 예시다. 이름을 정상/악성 보안 정답으로 사용하지 않는다.

출처: [README](https://github.com/cisco-ai-defense/mcp-scanner/blob/9e47aabdf2017b82e78f3419f39a75f20b6f98fa/README.md), [static 형식·API](https://github.com/cisco-ai-defense/mcp-scanner/blob/9e47aabdf2017b82e78f3419f39a75f20b6f98fa/docs/static-scanning.md), [readiness 예제](https://github.com/cisco-ai-defense/mcp-scanner/tree/9e47aabdf2017b82e78f3419f39a75f20b6f98fa/examples/readiness/sample_tool_definitions), [LICENSE](https://github.com/cisco-ai-defense/mcp-scanner/blob/9e47aabdf2017b82e78f3419f39a75f20b6f98fa/LICENSE). 저장소 라이선스는 Apache-2.0.

### S03. ClawHub Security Signals

데이터 카드는 MIT를 표시한다. 정제한 Skill 내용·일부 번들·버전·각 스캐너 신호·최종 판단을 제공한다. 논문 v1은 최종 판단을 자동화된 **silver label**로 설명한다. `clean`을 독립적인 안전 정답으로 삼지 않는다.

확인 시 데이터 카드 합계 67,453과 viewer 66,192가 달랐다. Cisco dataset lock은 변환 Parquet가 오래됐다고 기록하며 raw JSONL revision `69dcbd323c155312fb000ec89ea0b1efdf6a5757`를 고정한다. 이 revision은 **Cisco 기록에서 확인**한 것으로, 이번에 전체 원시 데이터를 내려받아 행수를 검산한 것은 아니다. 사용할 때 원본 revision·선정 ID·파일 해시·실제 행수를 다시 고정한다.

출처: [공식 데이터 카드](https://huggingface.co/datasets/OpenClaw/clawhub-security-signals), [논문 v1](https://arxiv.org/html/2606.01494v1), [Cisco 데이터 잠금 기록](https://github.com/cisco-ai-defense/skill-scanner/blob/431cb58a5ac333bc0bb9aaa23f7c30ac628f59f8/evals/datasets/public-datasets.lock.json).

한계: 자동 라벨의 순환 평가, 정제에 따른 입력 변화, 복제·계보 중복. 최신 Skill 한 건이 과거 승인·이전 버전 쌍까지 제공한다고 가정하지 않는다. 데이터 배포 조건과 원래 Skill의 개별 고지는 선택 사례마다 확인한다.

### S05. SkillSpector

main: `d162d9b343e559be13df8ebba093df3bc9d58c90`; API의 최신 release: `v2.11.2` (2026-09-09).

baseline·억제 결과 표시와 JSON 출력은 두 README에서 확인했다. main README는 `--fail-on-findings`, `--fail-on-incomplete` 및 완료 범위 처리를 설명한다. v2.11.2 README에서는 동일 문구를 확인하지 못했다. 릴리스에 기능이 없다고 단정하지 않고 실행 버전의 help/코드로 확인한다.

`--no-llm`은 LLM 분석을 끄는 설정이다. 공식 `v2.11.2` 태그에서 설치해 네 Skill을 실행했다. S01·S02·S03 모두 score 0, LOW, issues 0이었고, 구성요소 coverage는 100%였으나 workspace 형태 경로의 참조 해석 때문에 전체 completeness는 partial이었다. `--fail-on-incomplete`를 추가한 별도 실행은 정상 S00을 포함한 네 사례 모두를 exit 1로 차단했다. 실제 효과가 확인된 S01·S03의 관찰된 정적 검사 공백과 불완전성 gate의 방어 효과·정상 차단 비용을 함께 기록하며, 실행하지 않은 의미 분석 모드까지 실패했다고 확대하지 않는다.

출처: [고정 main README](https://github.com/NVIDIA/SkillSpector/blob/d162d9b343e559be13df8ebba093df3bc9d58c90/README.md), [v2.11.2 README](https://github.com/NVIDIA/SkillSpector/blob/v2.11.2/README.md), [release](https://github.com/NVIDIA/SkillSpector/releases/tag/v2.11.2). Apache-2.0 표기이며 실제 코드 도입 시 해당 커밋 LICENSE/NOTICE를 재확인한다.

### S06. NVIDIA 신뢰 파이프라인

공식 문서는 검사·과업 평가·Skill Card·디렉터리 서명을 구분한다. 서명 검증은 검토 대상 동일성을 확인하는 기존 수단이다. 검사와 서명만으로 모든 실행 환경의 안전성을 증명하지 않는다. 자체 fixture를 NVIDIA 공식 인증물로 표현하지 않는다.

출처: [공식 trust pipeline](https://docs.nvidia.com/skills/agent-skill-trust-pipeline). 문서의 절차를 참고하며 원문·로고·인증 표시를 우리 산출물로 재배포하지 않는다.

### S07. Snyk Agent Scan

출처: [0.6.3 당시 고정 README](https://github.com/snyk/agent-scan/blob/57fdd46e53ee833c63007c486477f17df4f65625/README.md), [0.6.3 release](https://github.com/snyk/agent-scan/releases/tag/v0.6.3), [현재 releases](https://github.com/snyk/agent-scan/releases). 코드·서비스·API의 이용 조건을 각각 확인한다.

### S08. MaliciousSkillBench

공식 카드의 9,740개 identity에는 출처·구조적 계보·근거 유형·split 정보가 있다. 정적 탐지 비교의 후속 후보로 적합하다. benchmark 메타데이터·파생 주석 등에 적용되는 CC-BY-4.0와 제3자 Skill 원문의 조건을 구분해야 한다. 정제본은 원본 바이트와 같은 공격 재현물이 아니다.

출처: [공식 데이터 카드](https://huggingface.co/datasets/ProtectSkills/MaliciousSkillBench). 현재는 카드 확인만 했으며 데이터 revision·행 ID는 미선정이다. 본 비교에 넣기 전에 이 둘과 라이선스·독립 판정 근거를 고정한다.

## 3. 기존 로컬 자료의 취급

`platform/experiments/capability-diff/README.md`와 `RESULTS-combined.md`에는 2026-09-17의 11쌍 비교 요약이 있다. 현재 체크아웃의 round1/2 `pairs/`, `results/`는 `.gitkeep`만 보유하고 round1 문서도 원본 미수집을 명시한다.

지정된 OneDrive의 `output/ai-supply-chain-design-research-2026-09-19` 하위 파일명·디렉터리명과 output 형제 폴더의 직속 항목에서도 해당 원본 이름을 찾지 못했다. 전체 드라이브·과거 채팅은 조사하지 않았다. 별도 local-pilot 기록은 있으나 같은 실험의 원본으로 확인되지 않았다.

따라서 이 기록은 **HISTORICAL_REPORT_ONLY**로 보존한다. 원본 입력·출력·명령·버전이 복구되기 전에는 새 비교의 측정값으로 인용하지 않는다. 특히 “점수가 같다 → 능력 변화를 놓쳤다 → 함수 이름만 본다”라는 인과 결론은 점수만으로 확정할 수 없다. 새 실험은 같은 경로 baseline, 정상/역방향 쌍, 전체 finding·범위 상태를 포함한다. 기존 파일은 수정하지 않았다.

## 4. 재사용 전에 남길 기록

선택 파일마다 `source_url`, commit/revision, 원본 경로, SHA-256, LICENSE·NOTICE, 수정 내역, 선정 이유, 라벨 근거, 정제 여부를 기록한다. 공개 접근 가능과 원문 재배포 허용을 동일하게 취급하지 않는다. 코드/자료를 실제 가져올 때는 platform의 `THIRD_PARTY.md`에도 기록한다.

이번 조회에는 연결된 GitHub 읽기 도구와 웹 도구를 사용했다. Firecrawl은 크레딧 부족으로 원문 조회가 실패하여 웹 원문 조회로 전환했다. 자료 확인과 향후 실험 결과는 별개다.
