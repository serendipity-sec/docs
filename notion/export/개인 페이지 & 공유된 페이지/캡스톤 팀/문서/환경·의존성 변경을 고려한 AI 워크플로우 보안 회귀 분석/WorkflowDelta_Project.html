A

파일 밖의 변경도 분석합니다.

n8n 리뷰 밖에 있는 하위 자원과 환경 증거를 검토 단위에 포함합니다. 부모 JSON이 같다는 이유만으로 기존 판정을 재사용하지 않습니다.[1]

B

기밀성과 입력 신뢰를 따로 추적합니다.

“외부 입력인가”와 “기밀자료인가”는 다른 속성입니다. TFA·CaMeL의 정보 흐름 관점을 참고하고, AI 요약을 자동 비식별화로 보지 않습니다.[4][6]

C

IF의 존재가 아니라 조건을 봅니다.

초기에는 상수 비교·허용목록·제한된 필드 선택만 해석합니다. 승인 경로와 조건을 명시적 정책으로 검사하며, 무관한 분기에는 안전성을 부여하지 않습니다.[7][8]

D

미확인을 안전으로 바꾸지 않습니다.

선언·정적 추론·모의 관측·제공자 확인을 구분하고 증거의 시각과 버전을 남깁니다. 실제 권한을 확인하지 못하면 미확인으로 표시합니다.[5]

TypeScript 기반 파서·분석 코어·CLI, 파일 기반 스냅샷, 로컬 HTML 보고서로 시작합니다. 실제 SaaS 권한 자동 수집은 후속 확장으로 두고, 초기 환경 프로필은 선언된 모의 증거임을 표시합니다.

04

최종 상세 아키텍처: 입력에서 재검토 판정까지.

핵심 분석은 하나의 로컬 프로세스에서 재현하고, 실제 실행이 필요한 시험만 격리합니다. 아래는 구현 기준으로 사용할 상세 설계이며, 완성된 시스템의 운영 실적이 아닙니다.

배포 전 분석 도구로 범위를 고정합니다. 입력은 변경 전·후의 워크플로우 묶음과 환경 증거이고, 출력은 위험 경로·깨진 가정·분석 한계가 연결된 검토 기록입니다. 분석기의 판정에 LLM을 사용하지 않습니다.

최종 판정은 네 가지로 고정합니다.

종료 코드는 제안 계약
PASS exit 0

범위 내 통과

필수 증거가 유효하고 중요 경로를 분석했으며, 금지 정책 위반·필수 시험 누락이 없습니다.

REVIEW exit 3

재검토 필요

중요 경로가 미지원이거나 권한 증거가 만료·부족합니다. 필수 시험·승인 근거가 없을 때도 통과를 보류합니다.

BLOCK exit 2

정책상 허용 불가

조직 정책이 금지한 가능 경로 또는 모의 시험에서의 위반이 확인됐습니다. 실제 유출 발생을 뜻하지는 않습니다.

ERROR exit 1

분석 실패

입력 형식 오류·검사기 실패 등으로 판정을 완성하지 못했습니다. 이전 PASS를 대신 사용하지 않습니다.

적용 순서: 유효한 분석이 불가능하면 ERROR. 분석이 완료됐다면 금지 경로가 있는 경우 BLOCK, 그렇지 않지만 중요 미확인이 있으면 REVIEW, 나머지는 명시된 범위에서만 PASS입니다. “새 위험 없음”만으로는 PASS하지 않습니다.

판정 ≠ 강제 차단P0는 결과 파일과 종료 코드를 제공합니다. 실제 배포 차단은 조직의 보호된 CI·배포 경로가 이를 강제할 때만 성립합니다. 운영 도구 호출의 실시간 차단은 본 프로젝트의 범위 밖입니다. 실행 직전의 구성 재확인과 보호된 배포 경로 연동만 P1 게이트로 확장합니다.

02

LLM 판정 대신 명시적 정보 흐름

CaMeL의 제어·데이터 흐름 분리와 AgentSpec의 명시적 제약을 참고합니다. 우리는 이를 배포 전의 제한적·결정적 분석에 적용하며, 두 연구의 런타임 보장을 구현했다고 주장하지 않습니다.[6][7]

03

읽기 전용 코어와 별도 시험 러너

후보 JSON·표현식·도구 설명을 코어에서 실행하지 않습니다. 외부 URL 자동 수집, 셸 실행, 업로드 플러그인 로딩을 금지합니다. 시험은 허용한 이미지·노드·모의 API만 사용하도록 설계합니다.

04

비밀 값과 조직 정책을 입력과 분리

n8n 내보내기에는 자격증명 이름·ID나 인증 헤더가 포함될 수 있습니다. 민감값은 입력하지 않는 계약으로 두고 의심 값은 거부합니다. 후보 파일은 정책·완료 기록을 직접 수정할 수 없습니다.[11]

05

전체 재평가부터, 최적화는 나중에

우선 전후 전체 평가를 정확도 기준으로 둡니다. 동일한 입력·정책·버전·검사 시각으로 결과를 재현한 뒤, 경로별 선택 재검사가 판정을 바꾸지 않는지 비교합니다. 외부 모델 호출과 대형 저장 인프라는 P0에 필요하지 않습니다.

06

실패와 미확인을 기록으로 남김

파일 크기·노드 수·재귀 깊이·분석 시간을 제한합니다. 한계에 도달한 중요 경로는 REVIEW, 검토 자체가 실패하면 ERROR입니다. 부분 파일을 완료 기록으로 승격하지 않고 임시 출력 검증 후 확정합니다.

신뢰하는 기반분석기 배포본·정책 관리자·승인된 증거 수집기·격리 실행기를 신뢰합니다. 이 기반의 관리자 권한 침해, 원격 MCP 내부의 숨은 행동, 실제 서비스의 모든 프롬프트 인젝션 방어는 이 아키텍처의 보장 범위 밖입니다. 보고서는 입력 문자열을 이스케이프하고, 실데이터·토큰을 로그나 보고서에 남기지 않도록 설계합니다.

설계의 중심은 새 스캐너를 더하는 것이 아니라, 구성 변경 → 영향 경로 → 정책 판단 → 검증 근거 → 재검토 결정을 하나의 검토 ID로 연결하는 것입니다.

05

차별점은 세 가지 비교 실험으로 입증합니다.

새로운 위험을 더 잘 찾는지, 무해한 변경의 재검토를 줄이는지, 무엇을 분석하지 못했는지를 함께 측정합니다. 아래 수치는 모두 제안한 실험 규모와 사전 목표입니다.

추가 연구는 후순위. 변경된 부분만 재검사하는 최적화는 핵심 분석이 완성된 뒤 진행합니다. 전체 재검사와 판정이 일치하는지 먼저 확인합니다.

06

예상 결과물은 분석기, 벤치마크, 증거 보고서입니다.

최종 발표에서는 부모 JSON이 같은 두 배포 조건을 비교하고, 왜 기존 승인을 다시 검토해야 하는지 실제 구현으로 설명하는 것을 목표로 합니다.
