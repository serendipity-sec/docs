## 3. "털기" 방향을 접은 이유

교수님 코드로 임팩트(뚫는 장면)를 만들려 했으나:
- XSS: `dangerouslySetInnerHTML` 없음 → React 기본 이스케이프 → 안 됨
- NoSQL 인젝션: `ObjectId.isValid()` + `.slice()` 방어 → 안 됨
- 터지는 건 **인증 부재 하나** → "로그인을 안 만들었네"로 임팩트 약함

결론: **잘 만든 코드는 안 털리고, 못 만든 코드는 털어도 안 놀랍다.** 임팩트를 "뚫기"에서
찾는 건 막다른 길. → A(만든 것으로 승부)로 전환.

## 4. 확정된 방향 (컨셉 v3)

**A 방향: 스캐너가 못 보는 "접근 규칙 검사"를 하는 도구를 만든다.**

- 결과물: 규칙 검사 엔진 1개 + 웹 얼굴(발표·시연) + CI 얼굴(실용·배포)
- 발표 3막: ① 스캐너 대비(1,109 vs 0) → ② 브라우저에서 실제 삭제 → ③ ~~AI 되먹임~~
- 상세: [후보1-컨셉-v3-확정안](후보1-컨셉-v3-확정안.md)

### ④ 부정이 3막을 바꿨다

당초 3막 = "규칙 파일 주면 AI가 처음부터 안전하게 짠다". 로컬 모델(qwen3.5:4b) 실험에서:
- 대조군 소유권 검사 0/3, 처치군도 0/3 — 규칙 파일 효과 없음
- 처치군은 기능마저 3회 다 실패 (규칙 지키려다 코드가 깨짐)

**교훈(코덱스 조언, 채택)**: 3막을 "규칙 파일 생성"에서 끝내면 안 된다. 규칙 파일을 넣은 뒤에도
**생성 코드를 다시 검사하고 A/B로 재검증해서, 규칙 위반이면 '완료'로 인정하지 않는** 흐름이어야 한다.
즉 우리 엔진(검사)이 AI 뒤에 계속 붙어 있어야 한다는 뜻 — 오히려 **엔진의 존재 이유를 강화**한다.

수정된 3막: "AI에게 고치라고 시킴 → **우리 엔진이 재검사** → 여전히 뚫림 → 통과할 때까지 반복" 
= "AI는 규칙을 줘도 놓친다. 그래서 검사가 계속 필요하다."
