## 0. 한눈에 보기

1. **도구는 많지만 서로 동의하지 않는다.**
   - ClawHub 운영 데이터: 스캐너 3개가 모두 플래그한 스킬은 0.69%뿐이다. 양성 플래그의 81.9%는 스캐너 1개에서만 나왔다 [P13].
   - 학계 측정에서도 5개 스캐너가 모두 악성으로 본 스킬은 0.12%였다 [P3].
2. **처음 보는 출처의 스킬에서는 성능이 무너진다.** 출처가 겹치지 않게 나눈 평가에서 재현율(recall)이 이렇게 나왔다: Cisco behavioral 2.5%, SkillSpector static 0%, SkillFortify 25.3% [P12]. Cisco의 자체 평가도 이 조건에서 recall 7.75%다 [G1].
3. **정적 도구는 설계상 우회된다.**
   - SkillCloak의 자기 추출 패킹(SFS Packing)은 스캐너 8종을 90% 이상 우회했다 [P9].
   - Adversa는 "모든 것을 악성으로 찍는 기준선(F1 0.655)을 이기는 스캐너가 하나도 없다"고 보고했다 [R3].
4. **LLM 판정은 강력하지만 판정기 자체가 공격 대상이다.**
   - 설득형 문구에 속아 승인한 사례가 있다 [R1].
   - 판정 모델에 따라 탐지율이 35%에서 95%까지 벌어진다 [P11].
5. **동적(샌드박스) 방식이 가장 강하지만 비용과 사각지대가 있다.**
   - SkillDetonate: 탐지율 97%, 오탐률 2%. 대신 스킬당 153초가 걸린다 [P9].
   - USENIX '26 파이프라인은 정밀도 99.6%. 대신 미확정 후보의 93.2%가 60초 실행 창 안에 발현되지 않았다 [P2].
6. **플랫폼 검증은 "다층 + 재검사"로 수렴 중이다.**
   - ClawHub: VirusTotal + 정적 분석 + SkillSpector + LLM 최종 판정 [P13, G8]. 매일 재검사 [M1].
   - skills.sh: Gen, Socket, Snyk 3사 감사 [M2].
   - Anthropic: Enterprise 조직에 업로드 시점 스캐닝, 2026-10-02부터 기본 활성화 [M4].
7. **외부 참조를 실제로 따라가는 도구는 SkillSpector의 `--transitive` 옵션 하나뿐이다.** 🔍 SSRF 방어는 설계되어 있다(호스트 허용 목록, 사설 IP 차단, 리다이렉트 재검증). 하지만 **GitHub, GitLab, Bitbucket, Hugging Face만** 따라간다. ClawHavoc가 쓴 붙여넣기 사이트 같은 **공격자 도메인은 구조적으로 보지 않는다** [G2].
8. **우리 프로젝트의 빈칸이 확인됐다.** "공격자 도메인까지 안전하게 따라가 수집하고 시점별로 비교하는" 도구는 이번 조사 범위에서 없었다 (11절).

## 1. 검사 방식 9가지

> 비유: 스킬을 **"택배 상자"**로 보면 이렇습니다.
> - 정적 검사: 상자를 **열어서 내용물 목록을 읽는 것**
> - LLM 판정: **사람(모델)에게 "이거 수상해?" 하고 묻는 것**
> - 동적 검사: **격리된 방에서 실제로 조립해 작동시켜 보는 것**
> - 외부 참조 추적: 상자 안의 **"나머지 부품은 이 주소에서 받으세요" 쪽지를 따라가 보는 것**

| # | 방식 | 입력 → 처리 → 판정 | 강점 | 구조적 약점 | 대표 |
|---|---|---|---|---|---|
| ① | **규칙·시그니처** (regex, YARA) | 파일 텍스트 → 패턴 매칭 → 매칭 개수·심각도로 점수 | 빠르고, 결정적(재현 가능)이며, 설명하기 쉽다 | 인코딩, 호모글리프, 줄 분할, 표현 바꾸기에 무력. 매칭 범위(파일 종류, 크기) 밖은 못 봄 | Huifer, SkillsDirectory, Cisco·SkillSpector의 1단계 |
| ② | **AST·데이터흐름(taint)** | 코드 → 구문 트리와 소스→싱크 흐름 추적 → 위험 흐름 보고 | 환경변수 → 네트워크 같은 **흐름**을 잡는다 | 지원 언어에만 적용. **자연어 지시는 대상이 아님.** 동적 생성 코드에 약함 | Cisco Behavioral, SkillSpector AST/TT, MalSkills [P6] |
| ③ | **형식 검증** (formal) | 선언 권한 ↔ 코드가 쓰는 권한을 추상 해석 → 위반 증명 | "위반 없음"을 **수학적으로 보장** (그 모델 범위 안에서) | 의도(악의)는 판단하지 않음. 모델이 단순함. 타이포스쿼팅·의존성 혼동 미탐 | SkillFortify [P5] |
| ④ | **LLM 판정** (LLM-as-judge) | 스킬 전체 또는 일부를 프롬프트에 넣음 → 모델이 판정 | 자연어 악의, 설명과 행동의 불일치를 잡음 | 비결정적. 비용. 컨텍스트 길이 제한. **판정기에 대한 인젝션.** 모델에 따라 성능 차이가 큼 | SkillVetBench [P11], Skillcop, AIG |
| ⑤ | **하이브리드 단계형** (규칙 → LLM → 다수결) | ①②로 후보를 거름 → LLM이 재판정 → 여러 모델 투표 | 비용 대비 정밀도가 좋음 | 1단계에서 놓친 것은 2단계로 안 올라감. ①과 ④의 약점을 모두 상속 | SkillSieve [P4], Cisco, SkillSpector, SkillGate [P10] |
| ⑥ | **주의집중(attention) 기반 위치 찾기** | 작은 모델의 attention으로 수상한 구간만 골라냄 → 큰 모델이 판정 | 긴 스킬 속 **숨은 악성 구간**을 찾아 토큰 절약 | 구간 분할에서 빠진 것은 놓침 (인라인 base64 등) | Locate-and-Judge [P8] |
| ⑦ | **저장소 문맥 분석** | 스킬 + 소속 저장소의 코드·README·메타데이터 → 일치도 점수 | **오탐을 크게 줄임** | 스킬만 단독 호스팅하는 레지스트리에서는 불가. 신뢰할 만한 저장소에 숨으면 통과 | Holzbauer et al. [P3] |
| ⑧ | **동적 실행** (샌드박스) | 컨테이너에서 실행 + 미끼 자격증명 + syscall·네트워크·파일 감시 → 행위 기준 판정 | 난독화·패킹과 무관하게 **실제 행위**를 봄 | 비용·시간. 시간 지연 트리거, 샌드박스 탐지, 조건부 실행. **외부 통신을 막으면 사슬이 끊기고, 열면 위험** | SkillDetonate [P9], USENIX [P2], MalSkillBench 검증 [P7] |
| ⑨ | **무결성·출처** (서명, 해시 고정, 재검사) | 서명과 해시 비교, 주기적 재스캔 → 변경 여부 | rug pull과 변조를 잡음 | "처음부터 악성"은 못 잡음. 외부 URL 내용 변경은 해시 범위 밖 | NVIDIA OMS 서명 [M3], skillwarden [G10], ClawHub 매일 재검사 [M1] |

**핵심 정리 (외워둘 것):**
- ①②③은 **"보이는 것"만** 본다.
- ④⑤⑥은 **"보이는 것을 이해"**한다.
- ⑧만 **"실제로 일어나는 것"**을 본다.
- ⑨는 **"바뀌었는지"**만 본다.
- **외부 URL 뒤의 내용은 ①~⑦ 모두의 사각지대이고, ⑧도 네트워크 정책에 따라 부분적으로만 본다.**

## 2. 분석 카드: 논문

> 형식: 한 줄 요지 / Q1 무엇을 탐지 / Q2 탐지 원리 / Q3 정적·동적 / Q4 실제 취약점 / Q5 놓치는 것 / Q6 Research Gap / 신뢰도 / 회의 질문

### [P1] SkillScan — *Agent Skills in the Wild* / 논문 / Liu et al., 2026.01, arXiv 2601.10338
- **요지:** 첫 대규모 측정 연구. 31,132개 중 26.1%가 취약. 탐지기 SkillScan을 제안.
- **Q1:** SKILL.md 본문 + 번들 스크립트(Python, Shell, JS). 4개 범주 14개 패턴.
- **Q2:**
  1. 정규식·키워드 정적 스캐너 (skill-security-scan v1.2.0)
  2. LLM-Guard 스캐너 10종 (인젝션, 시크릿, 비가시 텍스트 등)
  3. 둘 중 하나라도 걸리면 후보가 되고, Claude 3.5 Sonnet이 JSON으로 판정. 신뢰도 0.6 이상이면 확정.
  4. 정적 규칙의 판정을 LLM이 뒤집으려면 신뢰도 0.8 이상 필요 (비대칭 설계).
- **Q3:** 하이브리드 (정적 + LLM). 실행하지 않음. 동적 검증은 25개로 파일럿만 했고 72%가 실제 악성 행위로 확인됨.
- **Q4:** 클라우드 백업 위장 자격증명 탈취, 코드 리뷰 스킬의 주석 속 지시 등 (짝 문서 V02, V09).
- **성능:** 정밀도 86.7%, 재현율 82.5%. 기존 SAST(Bandit, Semgrep, Snyk Code)는 **프롬프트 인젝션 재현율 0%**.
- **Q5:** 미탐의 3대 원인 — 동적으로 조립한 URL, 자연어로 돌려 말하기, 지연 실행. 보안 도구 스킬(레드팀)은 정상인데도 오탐됨. 삭제된 17.3%에 따른 생존자 편향.
- **Q6:** "동적 검증을 전체 규모로" 하는 것이 저자가 밝힌 향후 과제 → 우리 샌드박스 방향과 일치.
- **신뢰도:** 프리프린트 (저자들의 후속작 [P2]는 USENIX 채택). 2026.01.
- **회의 Q:** "기존 SAST 도구로 되지 않나?" → SAST는 코드형은 절반 이상 잡지만 SKILL.md의 자연어 인젝션은 0% [P1 부록 F].

### [P2] *"Do Not Mention This to the User"* / 논문 (USENIX Security '26) / Liu et al., arXiv 2602.06547
- **요지:** 98,380개에서 정적 후보를 추리고 **샌드박스로 행위를 검증**해 악성 157개를 확정. 우리 아키텍처와 가장 닮은 선행연구.
- **Q1:** 코드와 지시문 양쪽. 13개 공격 기법.
- **Q2 (단계):**
  1. 정적 후보 추출: 14개 코드 정규식 + GPT-5.2 기반 지시문 분석 에이전트 → **4,287개 (4.4%)**
  2. Docker 샌드박스 실행 (Ubuntu 22.04, 2GB, 60초)
     - 감시: tcpdump, strace, auditd
     - **미끼 자격증명:** AWS_*, API_* 등 가짜 키
     - 스킬 호출: 문서화된 진입점 + LLM이 만든 합성 입력으로 3~5회 반복
  3. 동적으로 플래그된 762개를 두 명이 수동 검토 (κ=0.89) → **157개 확정**
- **Q3:** 하이브리드 (정적 선별 → **동적 검증**).
- **Q4:** 이메일 BCC 유출, 질문 도구 차단 (V03). 악성 스킬의 73.2%에 문서에 없는 숨은 기능이 있음.
- **성능:** 동적 검증 정밀도 99.6%. 가장 강한 정적 기준선보다 90배 개선. 보고한 스킬은 레지스트리가 100% 삭제.
- **Q5:** **시간 지연 트리거** — 미확정 후보의 93.2%가 60초 안에 발현되지 않음. Docker 탐지 후 행동을 억제하는 경우. 다중 세션이 필요한 1.9%. 게시자 한 명이 확정 악성의 54.1%를 차지하는 편중.
- **Q6:** 실행 시간 연장, 외부 통신 정책, 샌드박스 은폐가 남은 과제 → **우리가 차별화할 지점**.
- **신뢰도:** 동료심사 (USENIX Security '26). 2026.06 (v4).
- **회의 Q:** "우리 것과 뭐가 다른가?" → 이 연구는 네트워크를 tcpdump로 **관찰**만 한다. 외부 페이로드를 **안전하게 수집·재수집**하는 설계(SSRF 방어, 시점별 비교)는 다루지 않는다 (8, 11절).

### [P3] *Malicious Or Not* — 저장소 문맥 분류 / 논문 / Holzbauer et al., 2026.03, arXiv 2603.16572
- **요지:** 기존 스캐너가 과탐한다. 스킬이 속한 GitHub 저장소 문맥을 보면 플래그의 0.52%만 남는다.
- **Q1:** 스캐너가 플래그한 스킬 + 소속 저장소.
- **Q2:** 코드베이스 일치도(LLM 평가, 70%) + 메타데이터 성숙도(나이, 스타, 활동, 30%) → 저장소 문맥 점수.
- **Q3:** 정적 (문맥 분석).
- **Q4:** 버려진 저장소 탈취 경로(121개 스킬), ClawHub API 이메일 노출.
- **핵심 수치:** 스캐너별 판정률 3.8~41.9%. 5개 스캐너가 모두 동의한 비율 0.12%. 비용은 분석 1건당 약 0.002~0.01달러.
- **Q5:** 스킬만 단독 호스팅하는 ClawHub는 적용 불가. "신뢰할 만한 저장소 안의 악성"은 통과.
- **Q6:** 오탐 줄이기용 **보조 신호**로 쓸 수 있다.
- **신뢰도:** 프리프린트.

## 8. 외부 참조 추적과 fetch 안전성

> 프로젝트 지시사항 6장 대응. **이번에 코드를 직접 열어 확인** (2026-09-25 clone 기준).

### 8-1. 스킬이 외부 리소스를 참조하는 방식
| 방식 | 예 | 정적 추적 가능성 |
|---|---|---|
| 본문 속 URL | "설치 전 이 주소의 스크립트를 실행하라" (ClawHavoc) | URL 문자열은 추출 가능. **내용은 fetch해야 앎** |
| 스크립트 속 다운로드·실행 | `curl ... \| bash`, requests.get 후 exec | URL이 상수면 가능. **조립형이면 불가** [P1 미탐 원인] |
| 런타임 설정·지시 로딩 | 원격 JSON이나 MD를 읽어 지시로 사용 | 시점마다 내용이 다름 → **1회 fetch로 불충분** |
| 인코딩된 URL | base64 속 주소 (ClawHavoc) | 디코딩 전처리 필요 |
| 중간 경유지 | 붙여넣기 사이트(glot, rentry) → 실제 C2 | **다단계 리다이렉트·체인** |

### 8-2. 도구별 fetch 코드 확인 결과 🔍

**① NVIDIA SkillSpector `--transitive`** (v2.12.0) — **유일하게 외부 참조를 따라가는 도구**
- **추출:** 텍스트에서 `https?://` 또는 `git@` 토큰을 찾음. 이미지 배지 같은 호스트는 제외. 지원 확장자는 .md, .py, .sh, .json, .zip 등.
- **SSRF 방어 (`input_handler.py`):**
  1. **호스트 허용 목록:** git은 github.com, gitlab.com, bitbucket.org / 다운로드는 여기에 raw.githubusercontent.com, huggingface.co 추가
  2. **사설 IP 차단:** `getaddrinfo`로 모든 해석 결과를 확인해 private, loopback, link-local, reserved면 거부. **해석에 실패해도 거부** (fail-closed)
  3. **리다이렉트:** httpx `follow_redirects=False`로 두고 직접 따라감. **매 단계마다 호스트와 IP를 다시 검증**, 최대 5회
  4. **자원 제한:** 요청당 타임아웃 30초. 수집 크기 100MiB. transitive 전체는 대상 32개, 10MiB, 600초. 기본 깊이 1. 접두어 허용·거부 옵션
- **남는 약점:**
  - (a) **검증한 뒤 다시 해석하는 구조:** `_is_private_ip`에서 한 번 해석하고, httpx가 연결할 때 **다시 해석**한다 → 이론적으로 DNS rebinding 틈이 있다. 다만 허용 호스트가 대형 포지라 실제 위험은 낮다.
  - (b) **포지 4곳만 따라가서, 공격자 도메인·붙여넣기 사이트·IP 직접 주소는 아예 수집하지 않는다** → 가장 위험한 참조가 사각지대.
  - (c) 옵트인이고 1회 스캔이라 **내용 변경(rug pull)을 추적하지 않는다.**

**② Cisco skill-scanner `scan-repo`**
- 입력 저장소 URL을 **`https://github.com/`로 제한**하고 `git clone --depth=1` (타임아웃 120초).
- 스킬 내부 URL은 추적하지 않는다.
- 참고: SSRF **패턴을 탐지하는 규칙**(IMDS 169.254.169.254 등)은 ATR 규칙 팩에 있다. 이는 "스킬이 에이전트에게 SSRF를 시키는지" 탐지하는 것이고, 자기 방어와는 다르다.

**③ syedabbast/skill-scanner `--url`**
- `urllib.request.urlretrieve(url, ...)`를 **검증 없이** 호출한다.
- 호스트·스킴 제한, 사설 IP 차단, 리다이렉트 검증이 모두 없다.
- `urllib`은 `file://`도 처리하므로, **웹 서비스로 감싸면 SSRF와 로컬 파일 읽기 위험**이 생긴다 (CLI 단독 사용 시에는 사용자가 입력하는 것이라 위험이 작음).

**④ Snyk agent-scan** (MCP 쪽, 비교용 한 줄)
- 원격 MCP URL 접속 시 link-local과 메타데이터 주소는 차단한다. 하지만 loopback과 사설 주소는 허용하고, **DNS rebinding 틈을 스스로 명시**한다. 스킬 참조는 추적하지 않는다.

**⑤ Tencent AIG:** 원격 URL 입력을 지원한다고 적혀 있으나 fetch 코드는 **미확인**.

### 8-3. 추적할 때 도구 자신이 공격받는 지점
| 공격 | 설명 | 기존 처리 |
|---|---|---|
| SSRF (CWE-918) | 스킬 속 URL이 `169.254.169.254`나 내부 관리 페이지를 가리킴 | SkillSpector: 사설 IP 차단 + 허용 목록. syedabbast: 없음 |
| DNS rebinding | 검증할 때와 연결할 때 IP가 다름 | **아무도 IP를 고정(pinning)하지 않음** (확인한 범위) |
| 리다이렉트 우회 | 허용 호스트 → 302 → 내부 주소 | SkillSpector: 단계별 재검증 ○ |
| 압축 폭탄·거대 응답 | 스캐너 자원 고갈 | SkillSpector: 크기·항목 수·시간 제한 ○ |
| 부분 문자열 허용 목록 우회 | `github.com.attacker.com` | Huifer 취약 [R3]. SkillSpector는 정확 일치 또는 `.`+도메인 접미사 ○ |
| 판정기 인젝션 | 가져온 콘텐츠가 LLM 판정기를 조종 | 대부분 프롬프트 방어에 의존 [R1] |
| 스캐너 추적 노출 | fetch 자체가 공격자에게 "연구자가 보고 있다"는 신호 | P1 윤리 절에서 이 이유로 실행을 회피함. **클로킹(스캐너에게는 정상 응답)** 가능 |

→ **우리 설계에 바로 쓸 체크리스트:**
1. 해석한 IP로 **직접 연결** (rebinding 차단)
2. 매 리다이렉트마다 재검증
3. 스킴은 https·http만
4. 크기·시간·깊이 제한, fail-closed
5. **허용 목록 대신 "거부 목록 + 격리 egress"** (공격자 도메인도 수집해야 하므로)
6. 가져온 콘텐츠는 **데이터로만** 저장 (판정기 입력 시 이스케이프)
7. 시점별로 다시 가져와 해시 비교
8. 스캐너 식별을 피하도록 요청 특성을 다양화 (클로킹 대응, 선택 사항)

**우리 평가셋 설계 제안 (근거 포함):**
1. **출처 분리 분할**을 필수로 [P12].
2. **외부 참조형 표본**을 직접 설계: 무해한 로컬 C2 모의 서버를 쓰고, 참조 URL의 내용이 **시점에 따라 바뀌는** 쌍을 만든다. 기존 벤치에는 이 축이 없음 (확인 범위).
3. 난독화·패킹 변형을 SkillCloak 연산자 표로 생성 [P9].
4. 정상 표본은 **보안 도구형 스킬**을 포함해 오탐 측정 [P1, P3].

### 주의가 필요한 수치
- **SkillSieve F1:** 0.800 (논문 v1) vs 0.920 (CSA 인용) vs 93% (SkillSecurer 인용) → 버전 차이 가능성.
- **ClawHub 운영 구성:** 논문(2026.06, VirusTotal 포함) vs ClawScan README(2026.09, AIG 포함) → **최신은 README**. 둘 다 시점을 명시해서 인용할 것.
- **도구 개발사의 자기 벤치 성능** (AIG × SkillTrustBench, SkillFortify × 자체 벤치)은 외부 평가와 크게 다를 수 있음 [P12].
