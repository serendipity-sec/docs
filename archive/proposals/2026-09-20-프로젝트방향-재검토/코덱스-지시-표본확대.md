목표:
AI 코딩 도구로 만들어진 공개 웹앱 여러 개를 조사해서, 인증·소유권·권한 관련 보안 구멍이
"반복되는 패턴"인지 "우연"인지 확인한다. 목표는 취약점을 터뜨리는 것이 아니라,
같은 종류의 결함이 여러 앱에서 반복되는지를 세는 것이다.

■ 절대 지킬 것
- 배포된 실서비스에 절대 요청·스캔하지 마라. GitHub 소스 정적 분석 + 필요 시 로컬 실행만.
- 각 대상의 라이선스를 먼저 확인하고 README에 기록하라. 코드를 우리 저장소에 복사·커밋하지 마라.
  클론은 platform/experiments/sample-survey/targets/ 아래에만, .gitignore로 제외.
- 취약점 상세를 공개 이슈·외부에 올리지 마라. 보고서는 우리 비공개 저장소에만.
- 실제 계정·키·개인정보 사용 금지. 로컬 실행 시 더미만.
- 대상 코드 수정 금지.

■ 표본 선정 (10~15개 목표)
GitHub에서 다음 조건으로 AI 생성 웹앱을 찾아라:
- AI 생성 흔적: 저장소에 AGENTS.md / CLAUDE.md / .cursorrules / .lovable / "Generated with"
  커밋 메시지 / "Create Next App" 초기커밋 + AI 지침파일 조합 등
- 웹앱일 것: 인증·데이터 CRUD가 있는 것 (블로그·할일·예약·게시판·메모 등). 튜토리얼·정적사이트 제외
- 소규모(개인 프로젝트 규모), 최근 1년 내
- 스택 무관하되 정적 분석 가능한 것 우선 (Next.js/Express/FastAPI 등)
각 표본의 URL·고정 커밋·라이선스·스택·AI 흔적 근거를 표로 기록하라.

■ 각 표본에 대해 (정적 분석 중심, 실행은 선택)
1. 인증/세션이 있는가? (로그인·쿠키·JWT·세션 코드 존재 여부)
2. 쓰기 API(생성·수정·삭제)에 인증 검사가 있는가?
3. 자원에 소유자(ownerId/userId/authorId) 필드가 있는가?
4. 수정·삭제 시 "요청자 == 소유자"를 서버에서 확인하는가?
5. 관리자/역할 구분이 있는가?
6. AI 지침 파일(있다면)에 이 규칙들이 적혀 있는가?
→ 각 항목을 "있음/없음/해당없음/실행필요"로. 코드 근거(파일:행)를 남겨라.

■ 정적 스캐너 대조 (표본 3~4개만이라도)
- Semgrep CE를 로컬 컨테이너(--network none)로 돌려서, 위에서 사람이 찾은
  인증·소유권 결함을 Semgrep이 몇 개나 잡는지 대조하라. (가설: 거의 못 잡는다)

■ 결론 — 다음 질문에만 답하라
a. 표본 몇 개 중 몇 개가 "쓰기에 인증 없음" 또는 "소유권 검사 없음"이었는가? (숫자)
b. AI 지침 파일이 있는 표본에서, 지침에 접근 규칙이 적혀 있던 비율은?
c. Semgrep이 이 결함들을 잡은 비율은?
d. "AI 코딩이 인증·소유권 구멍을 반복해서 판다"가 이 표본에서 성립하는가?
   성립하면 몇 %, 성립 안 하면 그대로 보고. 표본이 작으니 비율은 신뢰구간 없이 "N개 중 M개"로.
e. 이 결과가 발표에서 "우와" 할 만한 임팩트가 되는가에 대한 담당자의 솔직한 판단.

■ 보고서 규칙
- "확인함/추정함/미실행" 구분. 실행 못 한 것을 "안전"으로 쓰지 마라.
- 표본이 편향됐을 가능성(AI 흔적이 있는 저장소만 골랐다는 점)을 명시하라.
- 각 표본을 비난하는 어조 금지. 패턴을 세는 중립적 기록.
- arXiv 2606.23130(9,041개 앱, broken access control 28.6%)과 우리 소표본 결과를 비교하되,
  우리 15개로 그 논문을 재현했다고 과장하지 마라.

## 결과 해석

| 나오면 | 의미 | 다음 |
|---|---|---|
| 15개 중 10개+ 가 인증/소유권 구멍 | **패턴 실재. B 방향 확정** | "AI 앱 X개를 봤더니 Y개가…"가 발표 첫 장면 |
| Semgrep이 대부분 못 잡음 | **우리 접근의 존재 이유 확정** | 도구를 만들 근거 |
| 절반 이하만 구멍 | 패턴 약함 | B의 "밝히기" 파트 축소, 다른 각도 필요 |
| AI 지침 파일에 접근 규칙 거의 없음 | Hidden security rules 재확인 | 논문 55%와 연결 |
