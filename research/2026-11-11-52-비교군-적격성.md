# n8n 보안 검증 선행연구와 비교군 적격성 (docs #52)

- 상태: **조사 1차본.** 비교 실험 결과가 아니다. 이 문서의 병합은 방법 채택이나 FlowDelta의 우수성을 뜻하지 않는다.
- 관련: [docs #52](https://github.com/serendipity-sec/docs/issues/52) · [docs #67](https://github.com/serendipity-sec/docs/issues/67) 1단계 · [docs #56](https://github.com/serendipity-sec/docs/issues/56) · [기존 조사 근거](../final/research-evidence.md) · [platform #99](https://github.com/serendipity-sec/platform/pull/99)
- 확인일: 2026-11-11. 버전·commit·라이선스는 이날 GitHub API·npm registry·arXiv에서 다시 확인했다.

## 1. 결론

1. **이번 후보 중 n8n AI Agent workflow의 전후 버전을 실행해 비교하는 공개 도구는 없다.**
   - 가장 가까운 0xCD4 lab은 전후 버전을 격리 실행한다. 다만 Webhook·Set·HTTP 쓰기 요청만 지원하고, AI·Code·credential 노드가 있으면 실행 전에 멈춘다.
   - 실제로 돌려 보니 n8n-claw 두 비교쌍 모두 `BLOCKED_UNSUPPORTED`(종료 코드 3)로 실행 전에 막혔다(platform #99).
2. **정적 공개 도구 5개는 n8n-claw의 취약 버전과 보완 버전을 구분하지 못했다.** 4개는 10월에 팀이 직접 실행했고([platform `experiments/n8n-claw-c`](https://github.com/serendipity-sec/platform/tree/main/experiments/n8n-claw-c)), 0xCD4 정적 검사는 11/11에 실행했다(platform #99). 이 결과는 "도구 공백"의 근거일 뿐, FlowDelta가 더 낫다는 근거는 아니다.
3. **n8n 전후 보안 회귀의 공개 정답셋은 이번 후보에 없다.**
   - JAW가 찾은 n8n 사례 8개는 코드·데이터가 공개되지 않았다.
   - AgentDojo의 과제는 n8n workflow가 아니다.
   - 그래서 [docs #28](https://github.com/serendipity-sec/docs/issues/28)에서 정답지를 직접 만든다. 교수님 요청(11/05 면담 5절)의 "공개된 것이 없으면 정답지를 직접 만든다"에 해당한다.
4. **#56의 외부 비교는 정적 기준선으로만 할 수 있다.** 동적 비교는 #56 설계의 내부 기준선과 한다. 내부 기준선은 전체 재분석 후 전후 비교, 고정·무작위 순서, 텍스트 검색이다.

## 5. 비교군 적격성 — #56에 넘길 목록

| 구분 | 후보 | 쓰는 방법 |
|---|---|---|
| 정적 기준선 (점수 비교 가능) | n8n Security Audit, FlowGuard, FlowSentry, Agentic Radar, 0xCD4 정적 audit | 같은 고정 버전에서 이미 실행함. 버전을 올려 다시 돌릴 때는 버전을 기록한다 |
| 동적 비교군 | **해당 없음** | 지원 표에만 남긴다. 0xCD4 rehearsal은 실제 실행에서 `BLOCKED_UNSUPPORTED`, JAW는 코드 미공개 |
| 방법 차용 (점수 비교 아님) | AgentDojo, JAW, Structural Coverage | 6절의 "가져다 쓸 것" |
| 확인 불가 | n8n-agent-vulntest-lab | 출처를 찾으면 다시 평가한다 |

정적 기준선과 FlowDelta는 판정 근거가 다르다. 정적 도구는 "경고가 바뀌었는가", FlowDelta는 "독립 관측으로 금지 효과가 생겼는가"를 본다. #56에서는 두 결과를 한 점수로 합치지 않고 따로 보고한다.

## 6. 이미 하는 것 · 가져다 쓸 것 · 우리가 검증할 차이

**이미 하는 것** — 이 부분은 FlowDelta의 최초 주장으로 쓰지 않는다.
- 전후 버전을 격리 실행하고 관측한 효과의 차이를 보는 것: 0xCD4 rehearsal. 다만 AI가 없는 HTTP 쓰기 요청만 다룬다.
- n8n workflow를 mock credential로 격리 인스턴스에 넣어 실행하고, 결정적 판정기로 성공을 정하는 것: JAW. 다만 단일 버전의 공격 탐색이다.
- 실행 전후 환경 상태로 정상 업무와 보안을 함께 판정하는 것: AgentDojo.
- workflow 그래프의 위험 경로를 정적으로 찾는 것: 0xCD4 audit, FlowGuard, Agentic Radar.

**가져다 쓸 것**
- AgentDojo: 실행 전후 상태 복사, 결정적 `utility()`·`security()`, 지표 3개(정상 업무 성공, 공격 아래 업무 성공, 공격 성공).
- JAW: canary 값, LLM이 아닌 결정적 판정기, mock credential import.
- Structural Coverage: 제한 도구 항목은 호출이 없었다는 사실만으로 충족되지 않고, 제한된 접근 시도가 명시적으로 관측돼야 한다(§III-A). 우리도 "위반 없음"을 효과가 안 보였다는 사실만으로 판정하지 않고, 시도와 그 결과를 독립 기록으로 남긴다. [#66 리뷰](https://github.com/serendipity-sec/docs/pull/66)의 독립 변경 기록 요구와 같은 방향이다. 변경된 간선을 시나리오가 얼마나 덮는지도 시험 충분성 지표 후보로 쓴다.
- 0xCD4: 미지원·증거 부족·정리 실패를 성공으로 세지 않는 fail-closed 원칙. 입력과 결과를 SHA-256으로 묶는 evidence manifest.

**우리가 검증할 차이** — 반증 가능한 가설과 실험

| 가설 | 반증 조건 | 실험 |
|---|---|---|
| H1. AI Agent n8n workflow의 전후 버전에서 소유권 회귀(남의 객체 쓰기)를 독립 상태 관측으로 판정할 수 있다 | 같은 비교쌍을 공개 후보가 구분한다. 또는 FlowDelta가 취약·보완을 구분하지 못한다 | #28 비교쌍 + #53 판정 계약으로 n8n-claw 전후 실행 |
| H2. 변경 정보로 시험을 고르면 같은 예산에서 확인하는 회귀가 더 많다 | 전체 재분석 후 전후 비교, 무작위 순서 대비 개선이 없다 | #56 동일 예산 비교 |
| H3. 변경된 경로를 덮는 시나리오가 회귀 확인에 기여한다 | 구성요소 제거 실험에서 그래프·검색을 빼도 결과가 같다 | #56 구성요소 제거 |
