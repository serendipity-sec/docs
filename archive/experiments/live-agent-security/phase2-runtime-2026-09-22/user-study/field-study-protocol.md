# 실제 사용자 승인 판단 연구 프로토콜

상태: **NOT_RUN**  
작성일: 2026-09-22  
범위: 외부 AI Skill·MCP 구성요소를 도입할 때의 승인·보류·거절 판단 지원

이 문서는 실제 사람 연구를 시작하기 위한 실행 프로토콜이다. 참가자를 모집하거나 동의를 받거나 응답을 수집하지 않았다. 표본 수, 모집 기간, 보상, 보관 기간, 기관 검토 필요 여부와 연구 담당자는 아직 확정하지 않았으며 모집 전에 채워야 한다.

합성 계측 파일럿의 `synthetic_dry_run` 기록은 연구 장치의 기록·집계 경로를 확인하기 위한 테스트 벡터다. 합성 actor를 사람 참가자로 바꾸거나 합성 결과를 실제 사용자 결과와 합치지 않는다. 실제 연구는 새로운 human run manifest와 별도 저장 위치를 사용한다.

## 1. 연구 질문

같은 원천 증거를 제공할 때, 버전·권한·변경·검사 완료 상태를 연결한 B1 표현이 기존 보고서 묶음 형태인 B0보다 다음 판단을 개선하는지 확인한다.

- 정책상 거절해야 하는 구성을 잘못 승인하는 판단.
- 정책상 승인 가능한 구성을 불필요하게 거절하거나 보류하는 판단.
- 증거가 부족한 구성을 승인 또는 거절로 단정하지 않고 보류하는 판단.
- 정확한 결정에 걸리는 시간과 확인한 근거.
- 틀린 결정에 높은 확신을 부여하는 과신.

사용성·호감·신뢰 응답은 보조 결과다. 신뢰가 올라갔다는 사실만으로 보안 판단이 개선됐다고 결론 내리지 않는다.

## 2. 시작 전 필수 관문

아래 항목이 모두 완료되기 전에는 모집과 본 trial을 시작하지 않는다.

1. 연구 책임자, 연락처, 기관의 윤리·연구 검토 필요 여부를 확정한다.
2. 모집 기준, 표본 수 근거, 보상, 보관 기간, 중단 기준을 사전 등록한다.
3. [`cases.json`](../../../../research/2026-09-21-검토공백과-기존도구-데모설계/cases.json)의 fixture를 실제로 만들고 원본·파생 관계를 고정한다.
4. 플랫폼·비교 화면을 보지 않은 두 검토자가 목적 P1과 증거를 바탕으로 ALLOW·HOLD·DENY를 독립 판정한다.
5. 불일치 해결 규칙을 적용하고, 해결되지 않은 사례는 HOLD로 남긴 reference set을 동결한다.
6. B0와 B1이 같은 원천 증거에 접근하며 한쪽에만 정답·추가 finding·설명 힌트가 들어가지 않는지 확인한다.
7. 각 case의 source evidence SHA-256과 B0·B1 presentation SHA-256을 기록한다.
8. 연습 과업과 본 과업을 분리하고, 지시문·기록·timeout·중도탈락 경로를 사람이 참여하지 않는 점검으로 확인한다.
9. `human-run-manifest.template.json`을 새 run 디렉터리로 복사한 뒤 연구 식별자와 동결된 입력 hash를 채운다. 원본 template를 결과 파일로 사용하지 않는다.

현재 이 관문들은 완료되지 않았으며 연구 상태는 `NOT_RUN`이다.

## 3. 참가자와 모집

모집 대상은 외부 Skill·MCP·플러그인·워크플로 구성요소의 도입 또는 검토와 관련된 사람이다. 개발 경험과 해당 구성요소 도입 경험을 최소한의 구간형 문항으로 기록하고, 경험 집단을 섞어서 배정한다. 학생·팀원처럼 연구자와 권력 관계가 있는 사람은 참여 거절이 불이익으로 이어지지 않음을 분명히 알린다.

모집 인원은 현재 `NOT_SET`이다. 초기 사용성 pilot과 효과 평가를 분리한다. pilot에서 큰 차이가 나왔다는 이유만으로 효과 평가 표본을 사후 축소하지 않는다. 실제 모집 전에 최소 관심 효과 또는 목표 정밀도, 반복 측정 구조, 자원 제한을 반영한 근거를 기록한다.

다음 정보는 모집 단계에서 수집하지 않는다.

- 개인 저장소 이름·URL, 실제 Skill/MCP 이름, 회사 내부 구성.
- API 키·토큰·비밀번호·개인 파일 또는 실제 프롬프트 기록.
- 정확한 직장·소속 부서처럼 재식별 가능성이 높은 세부 정보.

연락처가 필요하면 응답 데이터와 분리된 모집 목록에 보관하고 무작위 participant ID와 연결하지 않는다.

## 4. 비교 조건

| 조건 | 제공 자료 | 제한 |
|---|---|---|
| B0 | 기존 보고서·diff·카드·evidence pack을 원본에 가까운 묶음으로 제공 | B1에 없는 추가 정답·경고를 넣지 않음 |
| B1 | 같은 원천 증거를 버전, 권한, 변경, 검사 상태와 연결해 제공 | 새로운 분석 엔진·finding·전문가 결론을 추가하지 않음 |

B0와 B1의 원천 evidence hash가 같아야 한다. presentation hash는 달라도 된다. 한 조건에서만 파일을 더 열 수 있거나 교육 시간이 더 길어서는 안 된다. UI 효과와 분석 엔진 효과를 동시에 바꾸지 않는다.

## 5. 교차 배정

동일 참가자가 B0와 B1을 모두 경험하는 within-participant 설계를 사용한다. 사례를 두 평행 집합으로 나누고 다음 원칙으로 배정한다.

- 한 참가자는 같은 원본 또는 같은 원본의 변형을 두 조건에서 반복해서 보지 않는다.
- sequence 1은 집합 A를 B0, 집합 B를 B1로 보고 sequence 2는 반대로 본다.
- 경험 구간 안에서 sequence 배정 수가 가능한 한 균형을 이루도록 사전에 정의한 순환 규칙을 사용한다.
- trial 순서는 family와 reference decision이 한쪽에 몰리지 않도록 동결된 순서 목록 또는 재현 가능한 무작위 seed로 정한다.
- 실제 배정은 participant ID만 포함한 별도 allocation ledger에 저장한다. 연락처와 결합하지 않는다.

현재 `case-manifest.json`의 A·B 집합은 계측용 설계다. reference review와 난이도 검토가 끝나기 전에는 실제 참가자 배정에 사용하지 않는다.

## 6. 세션 절차

1. 담당자는 동의서의 최신 버전을 제공하고 질문을 받은 뒤 자발적 동의를 확인한다.
2. 참가자는 실제 비밀·저장소·업무 정보를 입력하지 말라는 안내를 읽는다.
3. 조건과 무관한 연습 사례로 ALLOW·HOLD·DENY 의미, 근거 요청, confidence 입력 방법을 익힌다. 연습 결과는 본 분석에 넣지 않는다.
4. 참가자는 각 본 사례에서 정책과 목적을 읽고 제공된 자료만 검토한다.
5. 참가자는 승인(ALLOW), 보류(HOLD), 거절(DENY) 중 하나를 선택하고 이유 코드와 추가로 필요한 근거를 기록한다.
6. 선택한 판단이 맞다고 생각하는 확신도를 0~100 범위로 기록한다. 이 값은 구성요소가 절대 안전할 확률이 아니라 **자신의 현재 판단이 맞다는 확신**이다.
7. 시스템은 trial 시작, 첫 evidence 열기, 최종 제출 시간을 기록한다. 페이지가 보이지 않는 시간이나 기술 중단은 별도 이벤트로 남긴다.
8. 참가자는 언제든 쉬거나 세션을 중단하거나 동의를 철회할 수 있다. 담당자는 결정을 유도하지 않는다.
9. 세션 종료 후 짧은 보조 사용성 질문과 자유 의견을 받을 수 있다. 본 판단 정답은 모든 본 과업이 끝나기 전에 공개하지 않는다.

## 7. 수집 필드

사람 응답 record는 `schema/human-study-trial.schema.json`을 따른다. 최소 필드는 다음과 같다.

- 무작위 participant ID, session ID, sequence ID, trial·case ID.
- B0 또는 B1 조건과 동결된 source evidence·presentation hash.
- ALLOW·HOLD·DENY 결정, 이유 코드, 요청한 추가 근거.
- 선택한 판단에 대한 confidence 0~100.
- 시작·첫 evidence·제출 시각과 소요 시간.
- timeout, 중도탈락, 기술 실패, facilitator 개입.
- 분석 제외 여부와 사전 정의된 제외 사유.

reference decision은 참가자에게 전달되는 trial record에 넣지 않는다. 동결된 별도 reference table과 분석 시 case ID로 결합한다.

## 8. 결과 정의

| 결과 | 정의 |
|---|---|
| 3분류 정확도 | 참가자 결정이 동결된 ALLOW·HOLD·DENY와 정확히 일치한 비율 |
| 위험 승인 | reference가 DENY인 trial에서 ALLOW를 선택 |
| 정상 거절 | reference가 ALLOW인 trial에서 DENY를 선택 |
| 정상 비승인 | reference가 ALLOW인 trial에서 DENY 또는 HOLD를 선택 |
| 적절한 보류 | reference가 HOLD인 trial에서 HOLD를 선택 |
| 불확실성 오승인 | reference가 HOLD인 trial에서 ALLOW를 선택 |
| 결정 시간 | trial 시작부터 제출까지의 시간. 정답 trial만 골라 계산하지 않음 |
| 근거 탐색 | evidence 열기 종류·횟수와 추가 근거 요청 |
| 과신 | 틀린 판단의 confidence 수준과 confidence-정확도 보정 관계 |

고확신 오류의 threshold, 주 결과, 최소 관심 효과, timeout 제한과 분석식은 첫 사람 응답을 보기 전에 사전 등록한다. 현재 값은 `NOT_SET`이다. 결과를 본 뒤 유리한 threshold나 지표를 선택하지 않는다.

시간 분석에는 오답, timeout, 중도탈락을 숨기지 않는다. answered trial의 시간과 모든 assigned trial의 상태를 함께 보고한다. timeout을 안전한 거절이나 보류로 간주하지 않는다.

## 9. 중도탈락·결측·제외 규칙

다음 규칙을 모집 전에 동의서와 사전 분석 계획에 맞춰 확정한다.

- 동의가 확인되지 않은 session은 수집을 시작하지 않고 분석에서 제외한다.
- 참가자가 동의를 철회하고 삭제를 요청할 수 있는 기간 안에 요청하면 연결 가능한 응답을 삭제한다.
- 이미 완전히 익명화되어 특정 응답을 찾을 수 없는 시점은 동의서에 사전에 설명한다.
- 세션 중단 전 제출된 trial은 동의 범위와 사전 계획이 허용하는 경우에만 부분 자료로 유지하고, 중도탈락 상태를 표시한다.
- timeout은 응답 없음으로 남긴다. HOLD·DENY·정답으로 대체하지 않는다.
- 화면 오류, hash 불일치, 로그 손상, 잘못된 case 표시, 정답을 암시한 facilitator 개입은 trial 수준 기술 제외 사유다.
- 연습 과업은 본 분석에서 제외한다.
- 느린 응답, 낮은 정확도, 가설과 반대되는 응답만을 이유로 사후 제외하지 않는다.
- 중복 참여, 자동화 응답, 비정상 세션을 판정하는 규칙은 첫 응답 전에 구체적으로 고정한다.

참가자·trial 제외 수와 사유는 조건별로 공개한다. 제외 후 결과만 제시하지 않고 배정·시작·완료·중단 흐름을 함께 보고한다.

## 10. 개인정보 최소화와 보관

- 응답에는 이름, 이메일, GitHub ID, 학번, IP 주소 원문을 저장하지 않는다.
- 연락처·보상 기록과 연구 응답을 서로 다른 저장 위치와 접근 권한으로 분리한다.
- 화면·브라우저 로그는 연구 페이지의 evidence-open·decision 이벤트로 제한한다. 전체 화면, 키 입력, 클립보드, 다른 탭의 URL을 수집하지 않는다.
- 자유 의견에 개인·조직 정보가 들어오면 분석본에서 비식별화하고 원문 접근을 제한한다.
- 음성·영상·화면 녹화는 기본적으로 수집하지 않는다. 필요할 경우 별도의 선택 동의와 보관 계획을 추가한다.
- 암호화된 저장 위치, 접근 가능한 역할, 보관 기간, 파기 방법을 모집 전에 manifest에 기록한다.
- 공개 결과는 집계값과 비식별 인용만 사용한다. 작은 경험 집단의 조합으로 개인이 드러나지 않게 한다.

## 11. 분석 경계

참가자의 여러 응답을 서로 독립적인 사람 수로 세지 않는다. 가능하면 참가자와 case의 반복 구조를 반영하고, 표본이 작으면 참가자별 분포와 사전 지정된 단순 비교를 우선한다. 조건 차이가 불확실하면 효과가 없다고 단정하지 않는다.

사용자 연구 결과는 기술적 공격 성공률과 별도다. 실제 모델이 악성 지시를 따른 기록을 사용자 오승인으로 바꾸거나, 사용자가 잘 판단했다는 결과를 runtime 차단 효과로 표현하지 않는다.

## 12. 파일과 결과 보관

실제 실행을 승인받은 뒤에만 다음과 같은 새 디렉터리를 만든다.

```text
results/human/<study-id>/
  human-run-manifest.json
  allocation-ledger.json
  trials.jsonl
  events.jsonl
  exclusions.json
  aggregate.json
  analysis.md
```

연락처·서명된 동의서·보상 기록은 이 디렉터리에 넣지 않는다. Git에 실제 개인 응답을 올리지 않는다. 공유 가능한 비식별 집계물의 공개 범위는 동의와 기관 요구를 확인한 뒤 별도로 결정한다.

현재 실제 human result 디렉터리는 없고, `human-run-manifest.template.json`과 `human-trial.template.json`은 빈 `NOT_RUN` 템플릿이다.
