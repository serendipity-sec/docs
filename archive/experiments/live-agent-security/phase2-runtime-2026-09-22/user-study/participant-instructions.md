# 참가자 안내문 템플릿

상태: **NOT_RUN / 배포 전 템플릿**

이 연구는 외부 AI Skill·MCP 구성요소를 사용할지 검토할 때 제공되는 보안 근거가 판단에 어떤 도움을 주는지 알아보기 위한 것입니다. 아직 실제 참가자에게 배포하지 않았습니다. 연구 책임자·연락처·예상 시간·보상·데이터 보관 기간은 모집 전에 확정하여 이 안내문에 기입해야 합니다.

## 참여 전 확인

- 참여는 자발적입니다. 참여하지 않거나 중간에 중단해도 불이익이 없습니다.
- 연구용으로 제공된 가상 자료만 사용합니다.
- 실제 API 키, 토큰, 비밀번호, 개인 파일, 회사·학교 내부 자료, 실제 저장소 주소를 입력하거나 붙여넣지 마세요.
- 질문이 있거나 쉬고 싶거나 중단하고 싶으면 언제든 진행 담당자에게 말할 수 있습니다.
- 동의서에 동의하기 전에는 본 과업을 시작하지 않습니다.

## 과업

각 사례에는 사용 목적과 허용 정책, 구성요소에 관한 검토 자료가 제시됩니다. 제공된 자료만 바탕으로 다음 중 하나를 선택합니다.

| 선택 | 의미 |
|---|---|
| 승인, ALLOW | 현재 제시된 목적·정책·검사 조건 안에서 사용할 근거가 충분함 |
| 보류, HOLD | 허용 또는 거절에 필요한 근거가 부족하며 추가 확인이 필요함 |
| 거절, DENY | 제시된 목적·정책을 위반하거나 필수 조건을 충족하지 못함 |

ALLOW는 미래의 모든 공격과 취약점이 없다는 인증이 아닙니다. HOLD는 악성이라는 뜻이 아닙니다. 근거가 부족할 때 억지로 승인이나 거절을 선택할 필요가 없습니다.

결정 뒤에는 다음을 기록합니다.

1. 판단 이유.
2. 더 필요하다고 생각한 근거.
3. 현재 선택한 판단이 맞다고 생각하는 확신도 0~100.

확신도는 구성요소가 절대 안전할 확률이 아니라 **내가 내린 승인·보류·거절 판단이 현재 근거에서 맞다고 생각하는 정도**입니다.

## 진행 중 유의사항

- 모든 메뉴나 파일을 반드시 열 필요는 없습니다. 평소 검토하듯 판단하세요.
- 진행 담당자는 정답이나 특정 결정을 암시하지 않습니다.
- 기술 문제가 생기면 임의로 다시 시작하지 말고 담당자에게 알리세요.
- 시간이 부족하거나 결정을 내릴 수 없으면 추측하지 말고 현재 상태를 알려주세요. 시스템은 timeout 또는 중단을 별도 상태로 기록합니다.
- 앞 사례의 답을 기억해 다음 사례에 적용하지 말고 현재 제공된 정책과 증거를 기준으로 판단하세요.

연구 시스템은 무작위 participant ID, 본 사례의 선택·이유·확신도, 연 증거 항목, 시작·제출 시간, timeout·기술 문제를 기록할 수 있습니다. 이름, 이메일, GitHub ID, IP 주소 원문, 전체 화면, 다른 탭, 키 입력, 클립보드는 연구 응답에 수집하지 않습니다.

구체적인 보관 기간, 접근 권한, 철회 방법은 동의서에서 확인합니다. 이 안내문과 동의서의 내용이 다르면 연구를 시작하지 말고 담당자에게 문의하세요.
