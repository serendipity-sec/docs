# 보안 점검 리포트 — 점검 계획 초안 (12주차, 11/20)

- 상태: **초안.** 담당은 아직 없다(docs #62에서 정함). 아래 결과 칸은 모두 비어 있다.
- 과제 기준: "적용 취약점 점검 결과, 대응 조치 내역" (15점, 보안 적용 수준)
- 점검 대상: FlowDelta 웹 서비스(platform #91~#96)와 화면 시안(Figma v1~v3). 근거는 각 이슈의 완료 조건(AC·U·I 번호)이다.
- 작성: 2026-11-12, 김민우

## 1. 방법

설계에 적힌 보안 통제마다 **실제로 막히는지 공격해 보고**, 증거(요청·응답·로그)를 남긴다. 통과·실패와 무관하게 결과를 그대로 적고, 실패하면 조치와 재점검 결과를 같이 적는다.

| 칸 | 적는 것 |
|---|---|
| 위협 | 무엇을 노리는가 |
| 통제 | 설계가 약속한 방어 (이슈·AC 번호) |
| 점검 방법 | 실제로 보낼 요청이나 파일 |
| 기대 | 막혔을 때의 응답 |
| 결과 · 증거 | 실제 응답, 로그 위치, 날짜 |
| 조치 | 실패 시 수정 PR과 재점검 |

환경: 11/19까지 구현된 범위는 로컬 Docker로, EC2 스테이징(#96 E-0~E-4)이 준비되면 거기서 다시 확인한다. 구현되지 않은 항목은 "미구현"으로 적는다. 통과로 적지 않는다.

## 2. 점검 항목

### A. 관리자 인증과 세션 (#94)
| # | 위협 | 통제 | 점검 방법 | 기대 |
|---|---|---|---|---|
| A1 | OAuth 로그인 위조 (CSRF·코드 가로채기) | `state`·PKCE를 서명 쿠키에 보관, `compare_digest` (U-AUTH-1·2) | `state` 바꾸기, `fd_oauth` 쿠키 빼기·위조, 만료 쿠키 재사용 | 400 |
| A2 | 조직 밖 사용자의 로그인 | 콜백에서 조직 멤버십 `active` 확인 (AC-9, U-AUTH-4) | 조직에 없거나 초대 대기 중인 GitHub 계정으로 로그인 | 403, 세션 없음 |
| A3 | 상태 변경 요청 위조 | `X-CSRF-Token` = HMAC(세션) (U-AUTH-3·8) | 토큰 없이·다른 세션 토큰으로 `POST /api/runs`, `POST /auth/logout`, `GET /auth/logout` | 403 / 405 |
| A4 | 세션 탈취 후 재사용 | 24h 만료, `HttpOnly`·`Secure`·`SameSite=Lax` (U-AUTH-5) | 만료 세션 재사용, 쿠키 속성 확인 | 401 `REAUTH_REQUIRED` |
| A5 | **탈퇴한 멤버의 계속 접근** | 멤버십은 로그인 때만 확인 | 로그인 뒤 조직에서 제거하고 접근 | **남는 위험**: 최대 24h 접근 가능. 조치 후보는 멤버십 주기 재확인이나 세션 만료 단축 |
| A6 | 토큰 노출 | 세션·CSRF·verifier를 로그에 남기지 않음, GitHub 토큰 미저장 (U-LOG-1) | 로그인 과정 서버 로그와 DB 검색 | 없음 |
| A7 | **로그인·콜백 엔드포인트 남용** (반복 요청) | 미기재 | `/auth/login`·`/auth/callback` 반복 요청 | **확인 필요**: 요청 횟수 제한이 설계에 없다 |

### B. 업로드 키와 업로드 처리 (#93, #94)
| # | 위협 | 통제 | 점검 방법 | 기대 |
|---|---|---|---|---|
| B1 | 키 위조·폐기 키 사용 | `fdk_<uuid>_<secret>` 파싱, SHA-256 상수 시간 비교, 폐기 확인 (U-KEY-1~4) | 형식 깨진 키, 다른 키의 uuid + 틀린 secret, 폐기 키 | 401 |
| B2 | **키 대입** | 미기재 | 같은 uuid로 반복 요청 | **확인 필요**: 시도 횟수 제한 없음 |
| B3 | 경로 조작·심볼릭 링크 아카이브 | 소켓 없는 bwrap 자식 프로세스만 아카이브를 열고, 부모는 `tarfile` 미사용 (AC-10, U-UPL-1~8) | `../` 경로, `/etc/passwd`를 가리키는 링크, 장치 파일이 든 tar | 거부, 호스트 파일 접근 없음 |
| B4 | 압축 폭탄·과대 결과 | 자식 stdout 9 MiB, 페이로드 1 MiB 상한 | 압축률 높은 tar, 파일 수만 개 | 400 `UPLOAD_RESULT_TOO_LARGE` |
| B5 | 샌드박스 없이 처리 | 자체 점검 실패 시 503 (사용자 결정 2(a)) | bwrap 제거·권한 제한 환경 | 503 `UPLOAD_SANDBOX_UNAVAILABLE` |
| B6 | 결과 위조 | 업로드의 `summary.json`은 무시하고 정상 검사를 다시 계산 (U-UPL-6) | `all_normal_checks_passed=true`로 바꾼 위조 결과 | 재계산 결과로 판정 |
| B7 | 저장소 고갈 | 케이스당 버전 상한 1000 (AC-11), 디스크 가드 | 반복 업로드, 디스크 여유 부족 | 409 `VERSION_LIMIT` / 503 `DISK_LOW` |

### C. 실행 오케스트레이터 (#93)
| # | 위협 | 통제 | 점검 방법 | 기대 |

| C3 | **웹 계층 침해가 호스트로 확대** | 단일 프로세스(Option A) | 웹 처리와 Docker 소켓의 같은 프로세스 공존 확인 | **남는 위험(#93에 명시)**: 웹 계층 침해가 곧 Docker 소켓 = 호스트 권한. 완화는 전용 OS 사용자, systemd 제한(#96) |

### D. 공개 페이지와 공개 API (#95)

- 공개 조건에 보안 판정이 없다 (D5).
