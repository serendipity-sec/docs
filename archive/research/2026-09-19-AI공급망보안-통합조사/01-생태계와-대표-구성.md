# AI 워크플로·에이전트 생태계와 대표 구성

조사 기준일: 2026-09-19. 공개 저장소 40개를 목적 표집해 README와 메타데이터를 보존했다. 전체 시장의 전수조사나 사용 점유율 조사로 해석하면 안 된다. 원본 URL·조회 시각·SHA-256은 `repository-inventory.json`에 있다. 이 문서는 조사 결과이며 아래 도구들을 설치하거나 운영했다는 뜻은 아니다.

## 1. 무엇을 프레임워크라고 부르는가

사용자가 GitHub에서 받는 것은 서로 다른 층에 걸쳐 있다. LangGraph 같은 실행 라이브러리, Dify 같은 제품형 플랫폼, Superpowers 같은 지침·스킬 묶음, OpenClaw 같은 실행 호스트를 모두 같은 종류의 프레임워크로 분류하면 검사 범위가 흐려진다.

| 층 | 역할 | 외부에서 받는 것 | 보안 검토의 중심 |
|---|---|---|---|
| 모델·API | 문장 생성, 분류, 추론 | 모델 가중치, API 제공자, 모델 설정 | 출처·데이터 전송·모델 식별·설정 |
| 실행 라이브러리 | 상태, 분기, 재시도, 도구 호출 관리 | Python/JS 패키지와 애플리케이션 코드 | 의존성·실행 권한·상태 격리 |
| 시각적 플랫폼 | 노드 연결로 작업 구성 | JSON/YAML 워크플로, 노드 플러그인 | 데이터 흐름·자격증명 참조·코드 노드 |
| 에이전트 호스트 | 세션·도구·파일·승인 관리 | 앱, 확장, 설정 | 실제 권한 강제·샌드박스·로그 |
| 지침·스킬 | 일하는 절차와 판단 기준 제공 | Markdown, 참조 문서, 스크립트 | 지침 출처·목적 적합성·추가 로딩 |
| 도구·연결 | 파일·DB·외부 서비스 호출 | MCP 서버, 플러그인, API 커넥터 | 서버 코드·도구 설명·인증·접근 범위 |
| 유통·운영 | 검색, 설치, 업데이트, 실행 관찰 | 레지스트리, 배포물, 잠금 파일, 추적 기록 | 버전 고정·서명·변경 이력·증거 보존 |

**API와 프레임워크는 대체 관계로만 볼 수 없다.** 프레임워크 안에서 상용 API를 호출하거나 로컬 모델을 쓸 수 있다. 단순한 한 번의 요청에는 직접 API 호출로 충분하고, 분기·재시도·여러 도구·지속 상태가 필요하면 실행 관리 도구가 유용해진다. 이 설명은 구조상의 관계이며 어느 방식이 시장에서 우세하다는 통계는 아니다.

### 현재 유지보수 상태의 주의점

조사 시점 AutoGen 공식 README는 유지보수 모드와 신규 사용자 대상 Microsoft Agent Framework 권고를 명시한다. 따라서 오래된 인기 순위만으로 AutoGen을 신규 개발의 기본 선택으로 추천하면 부정확하다. 반대로 기존 AutoGen 프로젝트를 조사 대상에서 빼야 한다는 뜻도 아니다. [공식 안내](https://github.com/microsoft/autogen)

## 3. 처음 써보는 사람이 보기 좋은 여섯 가지

| 이해하려는 것 | 먼저 볼 대상 | 예시 작업 | 실제로 살펴볼 물건 |
|---|---|---|---|
| API들이 어떻게 연결되는가 | n8n | 메일 수신 → 분류 → 저장 → 승인 요청 | workflow JSON, 노드·연결, credential 참조 |
| AI 앱을 어떻게 구성하는가 | Dify | 질문 → 문서 검색 → 근거 답변 | DSL, 모델·프롬프트·검색 노드·플러그인 |
| 분기·재개를 코드로 어떻게 만드는가 | LangGraph | 질문 분석 → 도구 → 검토 → 재시도 | 상태 정의, 노드 함수, 조건 엣지, 체크포인트 |
| 사람의 노하우를 어떻게 공유하는가 | Superpowers 또는 BMAD | 계획 → 구현 → 테스트 → 검토 | SKILL.md와 연결된 워크플로·참조 파일 |
| AI가 서비스에 어떻게 접근하는가 | MCP 예제 서버 | 파일 목록·문서 검색 | 서버 실행 설정, 도구 스키마·설명, 권한 설정 |
| 음성 분야도 같은 공급망이 있는가 | LiveKit Agents | 발화 → 인식 → 도구 호출 → 음성 답변 | STT/LLM/TTS 플러그인과 MCP·스킬 연결 |

이 목록은 사용자 팀이 구조를 이해하기 위한 선택이다. 유료 서비스 도입이나 실무 적합성을 검증한 순위는 아니다.

## 4. 실제 구성 파일에서 확인한 점

세 프로젝트의 파일 8개를 커밋 단위로 고정해 읽었다. `component-evidence.json`에 원본·해시가 있으며 내려받은 지침이나 스크립트는 실행하지 않았다.

- **Anthropic internal-comms:** SKILL.md가 소통 유형을 판별한 뒤 `examples/`의 지침을 읽도록 연결한다. 3P 예제는 Slack·Drive·메일·일정 같은 추가 정보원을 제안한다. 이는 도구 사용 의도가 있다는 근거이지 해당 권한이 실제 부여됐다는 증거는 아니다. [고정 원본](https://github.com/anthropics/skills/blob/34040c9c568585f6929bedeaad110ad08f079624/skills/internal-comms/SKILL.md)
- **Superpowers writing-plans:** 계획 수립 절차를 담은 실제 스킬 문서다. 플랫폼 런타임 자체와, 호스트가 읽어 따르는 작업 지침을 분리해서 모델링해야 한다. [고정 원본](https://github.com/obra/superpowers/blob/5bf4e78011075bcfc0dc295f0724994cd123ee71/skills/writing-plans/SKILL.md)
- **BMAD bmad-build:** 진입 파일에서 렌더링 스크립트를 거쳐 생성된 workflow.md를 읽는 구조를 확인했다. 단순 Markdown 검사는 실제 적용된 지침을 모두 보여주지 못할 수 있다. 렌더러·설정·생성 결과의 관계를 별도 증거로 남길 이유다. [고정 원본](https://github.com/bmad-code-org/BMAD-METHOD/blob/f033e70a2c0a3751aaab17dfdd29839ac621f541/skills/bmad-build/SKILL.md)

## 5. 증가가 실존하는가

현재 확인 가능한 결론은 **서로 다른 분야에 재사용 구성요소와 유통·보안 도구가 존재하며 발전하고 있다**는 것이다. GitHub 별 수, README 개수, 모델 다운로드 수만으로 기업 도입률이나 활성 사용자 증가율을 계산할 수는 없다.

Snyk는 2026-02-05 기준 스킬 표본 3,984개와 해당 유통 생태계의 게시 증가를 보고했다. Vercel은 skills.sh 보안 감사 연동을 발표했다. 이는 유통 활동과 운영상의 필요를 뒷받침하지만, 모든 AI 개발자가 프레임워크를 더 많이 쓴다는 증거는 아니다. [Snyk 조사](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/), [Vercel 발표](https://vercel.com/changelog/automated-security-audits-now-available-for-skills-sh)

발표에서는 “시장 전체의 사용률이 급증했으므로 필요하다”보다 “실제로 재사용·유통되는 지침과 도구에 공개된 위험 사례가 있고, 도입자가 변경 내용과 권한을 검토할 필요가 있다”는 논리가 현재 증거에 더 잘 맞는다.
