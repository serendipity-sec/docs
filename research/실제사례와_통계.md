# 실제 보안 사고 사례와 통계

조사일 2026-09-17 · 발표자료·제안서 보강용

> 제안서 v2에는 사례가 Acronis와 Cline **2건**뿐이다. 조사해보니 훨씬 많다.
> 대표 사례는 **ClawHavoc**을 쓴다. 아래 1-0을 먼저 읽을 것.

## 1-0. ★ 왜 postmark-mcp가 아니라 ClawHavoc인가

처음에는 postmark-mcp 사건(2025-09)을 대표 사례로 잡았다. npm 패키지 `postmark-mcp`가
v1.0.0~v1.0.15까지 깨끗하다가 v1.0.16에서 코드 231행에 BCC 한 줄이 추가되어 모든
이메일이 공격자에게 복사된 사건이다.

**그런데 이건 본질적으로 전형적인 npm 공급망 공격이다.**

- 공식 패키지 사칭 + 깨끗한 버전을 쌓은 뒤 악성 버전 게시
- event-stream(2018) 이후 계속 있던 패턴
- npm 쪽에는 이미 방어가 있다 — lockfile, 버전 핀 고정, Socket·Snyk

남는 AI 고유 요소는 **MCP 설정 관행** 하나뿐이다. `npx -y postmark-mcp` 처럼 버전 없이
쓰는 것이 표준이라 lockfile도 핀도 서명 확인도 없고 매 실행마다 최신을 당겨온다.
일반 프로젝트 의존성이었으면 `package-lock.json`이 v1.0.15에 묶어놨을 것이다.
**그런데 이것도 해결책이 이미 알려져 있다 — `postmark-mcp@1.0.15`로 핀 고정.**

→ 이 사례를 대표로 내세우면 "그냥 npm 공급망 문제 아닌가"라는 질문에
**"네 맞습니다"밖에 답할 수 없다.** 발표에서 쓰더라도 대표가 아니라 비교 기준점으로만 쓴다.

### 대신 ClawHavoc을 쓴다

**페이로드가 실행 코드가 아니라 자연어 지시문**이기 때문이다. 패키지가 아니므로
lockfile도 semver도 레지스트리 무결성 검사도 원천적으로 적용되지 않는다.

## 1. ★ 대표 사례 — ClawHavoc (2026년 2월)

### 규모

| 항목 | 값 |
|---|---|
| 검사한 스킬 | **2,857개** |
| 악성으로 확인 | **341개 (약 11.9%)** |
| 그중 Atomic Stealer 배포 | **335개** |
| 이후 Antiy 확대 조사 (2026-02-05) | 악성 패키지 **1,184개** / 발행 계정 **12개**, 한 계정이 **677개** |
| 이후 마켓 성장 | 2,857개 → **10,700개 이상**, 확인된 악성도 341 → **824개** |

### 공격 흐름

```
① 이름으로 위장          ② SKILL.md "설치 전제조건"      ③ 사용자가 그대로 실행     ④ Atomic Stealer
clawhub · clawhubb       실행 코드가 아니라              Windows: zip 내려받기      월 $500~1,000
youtube-summarize   →    "이렇게 설치하세요"        →    macOS: 스크립트 복붙   →   상용 정보탈취 도구
polymarket-trader        라는 문장
yahoo-finance-pro
```

**위장 수법** — ClawHub 타이포스쿼팅(`clawhub`, `clawhub1`, `clawhubb`), 암호화폐 도구
(Solana 지갑, 지갑 추적기), 트레이딩 봇(`polymarket-trader`, `polymarket-pro`),
유틸리티(`youtube-summarize`, `auto-updater-agent`), 금융(`yahoo-finance-pro`,
`x-trends-tracker`), Google Workspace 연동.

**"설치 전제조건" 섹션에 적혀 있던 것**

| OS | 지시 내용 | 실제로 일어난 일 |
|---|---|---|
| Windows | GitHub에서 `openclaw-agent.zip` 을 내려받으세요 | 키로거 트로이목마. **API 키·인증정보 수집** |
| macOS | `glot.io` 의 설치 스크립트를 복사해 터미널에 붙여넣으세요 | 난독화된 셸 명령이 `91.92.242[.]30` 에서 추가 페이로드를 받아 Mach-O 바이너리(Atomic Stealer) 실행 |

**탈취 대상** — macOS 키체인, 브라우저 비밀번호, 암호화폐 지갑, 텔레그램 세션, SSH 키.
일부 스킬은 리버스 셸 백도어를 심고 **`~/.clawdbot/.env`** 를 유출했다 —
**에이전트 본인의 자격증명이다.**

### 왜 이게 우리 프로젝트의 핵심인가

**스킬 파일에는 위험한 API 호출도, 취약한 의존성도, 유출된 자격증명도 없었다.
그냥 산문이었다.**

- OSV-Scanner는 알려진 CVE를 매칭한다 → 매칭할 의존성이 없다
- TruffleHog는 비밀정보를 찾는다 → 유출된 비밀정보가 없다
- Semgrep은 코드 패턴을 본다 → 코드가 없다
- 이건 이미 문헌으로 보고된 한계다

악성인 것은 **"이렇게 설치하세요"라는 문장**이고, 그 문장의 위험성은
**작업 목적과 대조해야만** 판단된다. 문서 요약 스킬이 왜 터미널에 스크립트를
붙여넣으라고 하는가 — 이 질문이 탐지 기준이다.

> 발표 문안 예시:
> "검사한 스킬 2,857개 중 341개가 악성이었습니다. 그런데 **그 파일들에는 악성 코드가
> 없었습니다.** 악성인 것은 '설치 전제조건'이라는 제목 아래 적힌 문장이었습니다.
> macOS 사용자에게는 스크립트를 복사해 터미널에 붙여넣으라고 했고, 그 끝에는
> 월 500달러짜리 상용 정보탈취 도구가 있었습니다.
> 기존 보안 스캐너가 이 파일에서 찾아낼 것은 아무것도 없습니다. 코드가 아니니까요."

## 1-1. 참고 — postmark-mcp (비교 기준점으로만)

| 버전 | 내용 |
|---|---|
| v1.0.0 ~ v1.0.15 | 전부 깨끗. Postmark 공식 GitHub 코드의 정확한 복사본 |
| **v1.0.16** | 코드 231행에 BCC 한 줄 추가 → 모든 이메일이 `phan@giftshop.club` 으로 |

주간 약 1,500 다운로드. 청구서·비밀번호 재설정 메일·내부 커뮤니케이션 유출.
Koi Security가 2025년 9월 발견. 최초로 실제 확인된 악성 MCP 서버 공급망 사고.

**쓰는 방법** — "npm에는 최소한 버전과 lockfile이라는 개념이 있는데도 MCP 설정이
그걸 안 쓰는 관행 때문에 당했다. **SKILL.md와 CLAUDE.md에는 lockfile이라는 개념
자체가 없다.**" 로 연결한다. 대표 사례로는 쓰지 않는다.

## 4. 탈취 대상 — 무엇이 실제로 털렸나

추상적으로 "위험하다"고 하지 말고 이 목록을 보여 주면 됩니다.

| 사건 | 페이로드 | 탈취 대상 |
|---|---|---|
| ClawHavoc | **Atomic macOS Stealer (AMOS)** | macOS 키체인 인증정보, 브라우저 데이터, 암호화폐 지갑, **텔레그램 세션**, SSH 키 |
| Oura MCP | **StealC** | 개발자 인증정보, 비밀번호, API 키, 암호화폐 지갑 |
| postmark-mcp | 자체 BCC | **청구서, 비밀번호 재설정 메일, 내부 커뮤니케이션** |
| ClawHub 전반 | 소셜 엔지니어링 후 명령 실행 | 거래소 API 키, 지갑 개인키, SSH 인증정보, 브라우저 비밀번호 |

공통점: **개발자 PC의 인증정보**가 표적이다. 학생 개발팀도 정확히 같은 표적이다.

## 5. 발표자료에 어떻게 넣을 것인가

현재 08번 슬라이드("왜 지침도 공급망 보안 대상인가")에 Acronis·Cline 2건만 있습니다.
이걸 **두 장으로 나누기를** 권합니다.

### 슬라이드 08 — 대표 사례 한 건 (신규)

> 제목: **악성 코드는 없었다. 악성인 것은 문장이었다**
> 그림: `assets/slide-clawhavoc사건.png`

공격 흐름 4단계 + "설치 전제조건"에 적혀 있던 실제 지시 + 탈취 대상 + 핵심 문장.

하단 강조:
> 스킬 파일에는 위험한 API 호출도, 취약한 의존성도, 유출된 자격증명도 없었다.
> OSV-Scanner·TruffleHog·Semgrep 같은 기존 도구가 여기서 찾아낼 것은 아무것도 없다.

### 슬라이드 09 — 사건과 통계 (기존 08 확장)

위 2장 타임라인에서 6~7건만 고르고, 3장 통계에서 4개 숫자만 뽑습니다.

추천 조합:
- 사건: postmark-mcp · ClawHavoc(1,184개) · Oura MCP(StealC) · mcp-remote(437,000) · nginx-ui(2,600) · Cline
- 숫자: **28,959 / 9,652** (버전이 서버의 3배) · **17%** (Bitdefender) · **81.9%** (단일 스캐너) · **90%+** (SkillCloak 우회)

> 각 숫자 옆에 "해석의 한계"를 한 줄씩 붙이세요. 지금 발표자료의 동향 표가 그렇게 돼 있고,
> 그게 이 발표자료의 가장 좋은 점입니다. 사례 표에도 같은 규율을 적용하면 됩니다.

## 6. 인용할 때 주의할 것

- **사건 유형을 섞지 말 것.** 악성 구성요소 유포(ClawHavoc), 정상 제품의 취약점(nginx-ui CVE),
  배포 계정 침해(Cline), 스쿼팅 후 백도어(postmark-mcp)는 **서로 다른 사건 유형**이다.
  합쳐서 "AI 공급망 사고 N건"으로 부풀리면 안 된다.
- **다운로드 수 ≠ 피해자 수.** 437,000은 영향 가능 환경 수이지 실제 피해자가 아니다.
- **17%는 한 마켓플레이스의 표본**이다. 전체 스킬의 악성 비율이 아니다.
- **"이건 그냥 npm 공급망 문제 아닌가"에 답할 수 있어야 한다.** postmark-mcp·Cline·Oura MCP는
  상당 부분 그렇다. ClawHavoc·GitHub MCP 인젝션·도구 설명 포이즈닝은 아니다 —
  **패키지가 아니고 페이로드가 자연어 지시문이기 때문**이다. 이 구분을 먼저 말하고 들어가라.
- **우리 도구가 이 사고들을 막았을 것이라고 주장하지 말 것.** postmark-mcp는 capability diff로
  **보여 줄 수 있었을** 유형이고, 그것도 사용자가 재검토를 했을 때의 이야기다.
  nginx-ui CVE나 Cline 계정 침해는 우리 범위 밖이다.
