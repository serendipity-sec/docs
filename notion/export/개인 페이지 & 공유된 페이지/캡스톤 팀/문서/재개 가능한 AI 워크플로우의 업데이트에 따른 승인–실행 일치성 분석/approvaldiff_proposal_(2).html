승인한 행동과 실행한 행동,
업데이트 뒤에도 같을까?

ApprovalDiff는 GitHub의 AI 워크플로우 업데이트가 사람의 승인을 다른 행동에 재사용하는지, 코드 비교와 실행 재현으로 검증하는 시스템입니다.

01 · Problem & evidence

각 버전은 정상이어도,
기존 승인을 새 버전에서 쓰면 달라질 수 있습니다.

연구의 핵심은 버전 전환 중의 승인 무결성입니다. 체크포인트는 중단 시 저장한 실행 상태를 뜻합니다. 아래는 분석하려는 결함을 설명하는 가상 시나리오입니다.

01

→

→

불일치 가능

A에게 보내는 승인이 B에게 보내는 실행에 사용됩니다. 그래프에 승인 노드가 있어도, 승인 대상 값과 실행 값이 연결되지 않으면 이 차이가 남습니다.

설명용 시나리오입니다. 실제 저장소 분석·취약점 재현 결과가 아닙니다. 값이 바뀌었을 때 재승인하거나 기존 값을 유지하는 구현은 정상 대조군입니다.

비교 요약: 기존 버전 A→A · 새 버전 B→B · 버전 전환 A→B · 수정 후 변경 감지 및 재승인

“각 버전을 따로 검사”하는 것과 “버전을 넘어서 승인이 보존되는지 검사”하는 것은 다릅니다.

왜 LangGraph에 집중하는가?[2][3]

승인 중단과 체크포인트 재개 동작이 명시되어 있어, 문서의 실행 의미를 모델과 대조할 수 있습니다. 플랫폼을 넓히기보다 한 의미 체계를 정확히 검증합니다.

왜 코드 비교만으로 끝내지 않는가?

경로가 존재해도 실제로 도달하지 못할 수 있습니다. 정적 후보와 프로그램 수준 재현을 분리해, 추정과 실행 증거를 혼동하지 않습니다.

왜 두 종류의 비교가 필요한가?[3]

각 버전을 처음부터 실행하는 검사와, 이전 체크포인트를 새 코드로 재개하는 검사를 모두 수행합니다. 단순 호환성 실패는 승인 위반과 별도로 분류합니다.

정상 예외: 사용자가 내용을 수정해 승인했다면 수정된 작업이 기준입니다. 승인된 필드의 동등한 표현 변경은 허용하며, 코드 해시가 달라졌다는 이유만으로 취약점으로 판정하지 않습니다.

핵심 범위

Python의 제한된 부분집합 · 명시적 LangGraph Graph API · 구조화된 승인 · 로컬 도구 구현 · 모의 전송 / 레코드 수정. 값 변경·재계산·공유 객체·도구 변경·승인 재사용·버전 전환의 6가지 결함 유형을 다룹니다.

보장하지 않는 범위

임의 Python 전체, 무제한 동적 코드·병렬 실행, 원격 서버 내부, 실제 계정 권한, 사용자의 UI 이해도. 분석 불가를 안전으로 표시하지 않으며, 모의 재현을 운영 환경의 공격 성공으로 확대하지 않습니다.

RQ1 · 추가 탐지

기존 검사보다 무엇을 더 찾는가?

Agent Audit의 신규 경고 모드, Agentproof의 구조 검사와 공통 지원 범위에서 비교합니다. 기준 도구를 실행하지 못한 사례는 실패로 집계하지 않습니다.

측정: 정밀도 · 재현율 · 정상 변경의 오탐

RQ2 · 기여 분리

재개·버전 전환 모델이 필요한가?

값 추적, 재개 의미, 버전 전환 검사를 각각 제거한 버전과 비교합니다. 단순히 규칙 수가 많아서 좋아진 결과인지 구분합니다.

측정: 기능별 누락 차이 · 추가 설명 가능한 사례

RQ3 · 재현성과 적용성

경고가 실제 실행으로 확인되는가?

승인 요청과 최종 도구 인자를 대조하고, 공개 코드에서 수동 설정량과 분석 불가 원인을 기록합니다. 수정 후 정상 작업도 유지되는지 확인합니다.

측정: 재현 성공률 · 판단 불가 비율 · 분석 비용

평가의 신뢰성정답은 두 명이 독립 검토합니다. 인위적인 변형과 실제 공개 코드의 발견을 분리하고, 포크·템플릿 복제본을 독립 표본처럼 세지 않습니다.

연구의 완성 기준새 CVE 발견을 전제하지 않습니다. 정의한 결함의 정상·위험·수정 사례, 실행 증거, 실패 사례까지 재현 가능하게 공개하는 것이 기준입니다.

우리가 확인할 결론: “승인 관계와 버전 전환을 함께 분석하는 것이, 어느 조건에서 기존 검사에 추가 가치를 주는가?” 결과가 제한적이면 그 범위도 함께 보고합니다.

02

03

비교 실험 보고서 + 연구 아티팩트

선행 도구 비교, 기능 제거 실험, 적용 범위와 실패 원인을 공개합니다. 타 연구자가 결과를 검토·재현할 수 있는 패키지가 목표입니다.

4인 연구 모듈 · 정적 분석 / 관계 검증 / 실행 재현 / 실증 평가·통합

범용 AI 보안 플랫폼이 아니라, 사람이 부여한 권한이 코드 변경과 실행 재개를 거쳐도 보존되는지 검증하는 연구입니다.

근거 자료

공개 원문 확인 기준: 2026.10.01 · 수치와 기능은 해당 자료의 범위에 한정

01
선행논문 · arXiv v1
Loopjacking: Hijacking Human-in-the-Loop Approval ↗

§3–4: Agno 7개 릴리스, 조건부 LangGraph Agent Server 구성 12개 버전의 재현 보고. 특정 실험 구성의 결과이며 생태계 발생률이 아님. 승인–실행 불일치의 위협 모델에 사용.

02
공식 문서
Interrupts ↗

중단된 노드는 재개 시 처음부터 다시 실행될 수 있음. 승인 payload, resume 값, 사용자 수정 승인 패턴의 의미를 모델링하는 근거.

03
공식 문서
Backward compatibility ↗

기존 스레드의 저장된 상태에 최신 그래프가 적용되는 동작과 기술적·업무적 호환성의 구분. 버전 전환 검사의 직접 근거.

04
선행논문 + 공개 프로젝트
Agent Audit: A Security Analysis System for LLM Agent Applications ↗프로젝트 저장소 ↗

데이터 흐름·자격증명·설정·권한 위험 분석. 공개 저장소의 baseline 모드는 커밋 간 신규 경고를 표시하므로, 단순 경고 diff를 차별점으로 주장하지 않음.

05
선행논문 · arXiv v1
Agentproof: Static Verification of Agent Workflow Graphs ↗

§2, §4, §7: 그래프 구조·시간적 정책 검증과 승인 게이트 우회 검사. 승인 노드의 존재나 경로 검사 자체는 기존 기여임.

06
공개 프로젝트 문서
ctrlrun-langgraph ↗

승인 인자를 전달하는 설정에서 재구성한 작업의 해시를 비교해 불일치를 거부. 승인–행동 결합 방어의 비교 대상이며, 모든 설정이 동일하게 방어하는 것은 아님.

07
공개 프로젝트
Agent Security Regression Harness ↗

시나리오·실행 기록의 정책 검증과 LangChain/LangGraph invoke 대상 실행을 지원. 테스트 실행기와 코드 변경에서 재현 조건을 도출하는 로직을 구분.

프로그램 검증 연구 · CAV 2012
