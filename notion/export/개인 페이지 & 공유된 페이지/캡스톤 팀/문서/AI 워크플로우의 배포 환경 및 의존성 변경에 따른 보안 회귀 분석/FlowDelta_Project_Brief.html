02
Problem & threat model

“업데이트 후에도 이전 검토가 유효한가?”

보안 회귀란 변경으로 인해 이전에는 없던 위험이 생기는 것입니다. 아래 사례를 전환하면 분석기가 설명해야 할 차이를 볼 수 있습니다.

대표 사례 · 외부 문의를 읽는 사내 문서 지원 에이전트설명용 예시 · 실제 스캔 아님
가정한 정책기밀 문서의 수신자는 지정된 내부 메일함으로 제한합니다. 외부 입력은 신뢰하지 않습니다.
BEFORE · 검토된 구성

AFTER · 검토 대상

외부 문의가 수신자 선택에 영향을 줄 수 있습니다.
재검토 필요

수신자 결정 범위가 확대되었습니다.

외부 문의 → AI 판단 → 발송 대상 선택 경로가 생깁니다. 같은 에이전트가 기밀 문서도 조회할 수 있어 목적지 제한을 다시 확인해야 합니다.

판정 범위: 가능한 위험 구조입니다. 실제 프롬프트 인젝션 성공이나 유출을 입증한 것은 아닙니다.

공격자와 변경 권한악성·침해된 공급자는 배포 파일이나 제공된 하위 워크플로우를 바꿀 수 있습니다. 별도의 외부 공격자는 문의·문서·도구 응답에 영향을 줄 수 있다고 가정합니다.
신뢰 경계보안 정책은 도입 조직이 정의합니다. 운영자 선언, 수집기가 관측한 사실, 분석기의 추론을 구분합니다. 공급자가 붙인 “안전함” 표시는 증거로 간주하지 않습니다.

표는 공개된 기능·논문을 기준으로 연구 질문을 구분한 것입니다. 기존 제품에 해당 기능이 전혀 없다고 단정하거나 탐지 성능의 우열을 주장하지 않습니다. 학술적 차별성은 비교 실험으로 검증합니다.

① 데이터와 판단 영향의 분리

정보가 어디로 전달되는지와, 외부 입력이 수신자·URL·도구 선택에 영향을 주는지를 따로 추적합니다.

② 환경까지 포함한 보안 변경

상위 파일에 차이가 없어도 계정·변수·하위 워크플로우의 변화가 기존 검토 조건을 깨뜨리는지 분석합니다.

③ 변경 중심의 재현 가능한 평가

위험 변경만이 아니라 동작을 보존한 정상 변경과 분석 불가 사례를 공개 벤치마크로 구성합니다.

04
Final system architecture

두 배포 구성을 분석하고, 보안 의미의 차이를 설명합니다.

코어는 입력을 실행하지 않는 로컬 분석기입니다. 권한 수집과 실행 재현은 명시적으로 분리된 경로로 둡니다.

개발 구성TypeScript 기반 파서·분석 라이브러리와 CLI, 구조화 JSON·SARIF·HTML 출력, Python 평가 도구, 별도 격리 실행 러너를 구현합니다.

분석 결과의 재사용 조건워크플로우뿐 아니라 하위 의존성·환경 연결·정책·분석기 버전이 달라지면 영향 범위를 다시 확인합니다. 대응이 불명확한 변경은 정상으로 단정하지 않습니다.

05
Design decisions & rationale

설계 선택마다, 막으려는 실패가 있습니다.

선행 접근은 재사용하되, FlowDelta가 해결할 문제에 맞춰 분석 단위와 판단의 경계를 정합니다.

01

노드 연결이 아니라 필드·실행 의미를 모델링

민감 필드의 전달, 분기 조건, 항목 대응, 하위 호출을 분리한 중간 표현을 만듭니다.

근거와 선택 이유

n8n은 이전 노드의 데이터 항목 연결을 추적합니다. 연결 오류도 존재하므로 화면의 선만으로 데이터 출처를 판단하면 부정확합니다. [13]

02

민감정보 흐름과 AI 판단 영향을 분리

“본문에 무엇이 들어가는가”와 “누가 수신자를 결정하는가”를 독립적으로 추적합니다.

근거와 선택 이유

모델은 문맥·도구·입력에서 도구 인자를 채울 수 있습니다. CaMeL의 제어·데이터 분리 원칙도 참고하되, 여기서는 가능한 위험 경로를 정적으로 분석합니다. [11] [9]

03

검토 단위를 배포 묶음과 환경으로 확장

상위 JSON, 제공된 하위 워크플로우, 연결 계정·권한, 정책을 함께 비교합니다.

근거와 선택 이유

n8n은 이미 의존성을 포함하는 패키지 구조를 제공합니다. 새로운 목록 포맷을 발명하기보다 기존 입력에서 보안 영향을 계산합니다. Preview 포맷은 버전을 고정합니다. [14]

04

승인 노드의 존재가 아니라 보호 경로를 확인

위험 동작으로 가는 경로가 승인 절차를 우회하는지, 실제 실행 인자가 검토 대상인지 확인합니다.

근거와 선택 이유

n8n 공식 가이드도 모델이 요약한 승인 문구가 아니라 실제 도구 인자를 보여줄 것을 권고합니다. 검증한 승인 구성만 보호 조건으로 인정합니다. [12]

05

미확인은 안전이 아니며, 정적 코어는 실행하지 않음

임의 코드·동적 참조·관측 불가 권한은 명시적으로 남깁니다. 핵심 판정은 규칙과 분석으로 재현합니다.

근거와 선택 이유

일부 MCP 검사는 설정된 명령을 실제 실행합니다. FlowDelta는 이 경로를 코어에서 제거하고 권한 수집·실행 시험을 분리합니다. [6]

깊이는 확보하고, 범위는 제한합니다.

포함 · 구현 목표약 20개 노드 유형의 지정 동작·버전, 제한된 JavaScript 표현식, 제공된 하위 워크플로우, 계정·권한 스키마와 PostgreSQL 수집기 1종, 지원되는 승인 경로를 다룹니다.

제외 · 보장하지 않는 영역임의 JavaScript 전체 분석, 원격 MCP 내부 구현의 완전 검증, n8n·운영체제의 미공개 취약점, 모델 자체 백도어, 범용 런타임 방화벽은 핵심 범위 밖입니다.
