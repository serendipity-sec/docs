## 기존 규칙과 대조

[팀 온보딩](../../팀-온보딩.md)의 현재 원격 규칙은 docs가 사람별 브랜치에서 본인 Merge pull request, platform이 팀원 1명 승인 후 squash이며 어느 쪽도 main에 직접 push하지 않는 것이다. 검사에 빨간불이면 병합하지 말라는 규칙도 있다. 개인 질문만으로 기존 규칙을 변경하지 않는다.

### 별도 GitHub 조회와 규칙의 적용 범위

**10/23 KST**, 인증된 GitHub API의 workflow 목록을 읽었다. [platform Actions](https://github.com/serendipity-sec/platform/actions)의 auto-label·flowdelta-ci·main-push-guard·pr-check·review-check·secret-scan 여섯 YAML workflow는 **disabled_manually**였고, [docs Actions](https://github.com/serendipity-sec/docs/actions)의 다섯 YAML workflow는 **active**였다. 두 저장소의 동적 Dependabot/Dependency Graph 항목은 active다. 조회 시점의 설정이며 실제 검사 통과·중단 원인 확인이 아니다. 설정을 변경하지 않았다.

현재 원격 [팀 온보딩](../../팀-온보딩.md)은 여전히 빨간불이면 병합하지 않으며 docs는 본인 merge commit, platform은 팀원 1명 승인 후 squash라고 적는다. **Slack 공지의 “모든 workflow”를 docs까지 비활성화됐다는 사실로 일반화할 수 없다.** 공지의 저장소·기간·리뷰 기준과 문서 규칙을 어떻게 맞출지는 미확인으로 남긴다. 최종 합의 근거 없이 원격 규칙·팀 역할을 바꾸지 않는다.

이 예약은 사용자가 지정한 **실제 CI 모두 성공 후 병합** 조건을 유지한다. 수집된 공지를 검사 생략·설정 변경의 실행 지시로 사용하지 않았다. 코드·데모·결제/한도 화면·세부 장애는 이번 수집에서 검증하지 않았다.
