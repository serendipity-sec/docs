## 이번에 확보한 근거

- **논문·학술 연구 28편**을 확인 범위와 함께 정리했다. 최초 12편에 IntentCap·SkillGuard·Fides·PCAS 등 16편을 추가했다. **28편 전체 정독·재현을 뜻하지 않는다.** 추가 웹 검색 48개와 출처 추적·제외 사유를 [기록](evidence/deep-web-research.json)했다.
- 최초 5개에 **공개 구현/평가 저장소 5개와 공식 확장 명세 저장소**를 추가 확인했다. code path·commit·읽은 범위를 구분했다. SkillGuard의 hook은 미확보 gitlink 아래여서 구현 검증에서 제외했다.
- Cisco 검사기 2종, CompoSkill의 **그래프 함수**, IntentCap의 **정책 checker**를 제한적으로 실행했다. IntentCap은 합성 4조건·5이벤트가 예상대로 판정됐다. 이는 기존 기능 확인이며 보안 성능 재현이 아니다. [실행 근거](evidence/intentcap-checker-results.json)
- Cisco Skill Scanner **2.1.0**은 `private` 읽기 Skill과 `webhook` 발행 Skill을 함께 검사할 때 `CROSS_SKILL_DATA_RELAY`를 보고했다. 두 Skill 각각의 finding은 0개였다. **기존 도구가 결합 위험을 전혀 못 본다는 주장은 틀린다.** [실행 근거](evidence/skill-scanner-results.json)
- MCP 도구 이름으로 기술한 읽기/발행 Skill 쌍과 단일 보고 Skill에서는 같은 오프라인 모드가 finding을 보고하지 않았다. **실제 침해를 재현한 결과가 아니라, 입력 표현과 분석 범위에 따른 차이**다.
- Cisco MCP Scanner **4.8.4**의 YARA 모드에서 일반 도구 2개는 무경고였다. 무해한 지시 덮어쓰기 문장도 표현에 따라 탐지 결과가 달랐다. LLM·API 분석기까지 실패했다고 확대 해석하면 안 된다. [실행 근거](evidence/mcp-scanner-results.json)

## 회의에서 제안할 범위

**우선 탐지 대상:** 비공개 자료를 읽고 요약·가공한 뒤 허용되지 않은 공개 대상에 보내는 경로. 읽기나 발행 기능 자체보다 **자료의 등급, 전달 경로, 대상의 접근 범위, 사용자 승인**의 조합을 검사한다.

**첫 구현:** 제공된 정적 자료 → 연결·권한 근거 복원 → 명시적 계약과 모순/누락 검사 → 고정된 기존 정책 엔진과 비교 → 위험 후보/통제에 막힌 경로/근거 부족 표시. 근거 추출 성능과 정책 검사 성능을 나눈다. 공식 Skills over MCP의 서버별 식별·manifest·승인 수명은 기본 요건으로 반영한다.

**차별성 검증 기준:** IntentCap·SkillGuard·Fides/PCAS의 가정을 검토하고, harness-eval·skil·Cisco 교차 검사·TFA와 적용 범위를 맞춰 비교한다. **기존 방법에도 같은 근거를 제공했을 때 이득이 유지되는가**가 핵심이다. 성능 차이가 사라지면 새 탐지법 주장을 접고 근거 복원·배포 감사 또는 비교 실증 기여로 제한한다.
