# FlowDelta — 업무 자동화를 고친 뒤에도 안전한지 확인해 주는 서비스

**팀 serendipity** · 웹어플리케이션보안 캡스톤 2026-2 · 김민우, 박용준, 양유상, 장준서

## 한 줄 소개

n8n 같은 업무 자동화 도구로 만든 워크플로를 수정했을 때, **고친 버전이 예전보다 위험해지지 않았는지** 고치기 전과 후를 똑같은 조건에서 실제로 실행해 비교하고 결과를 웹으로 알려 줍니다.

## 왜 필요한가

- 회사들은 n8n으로 주문 조회, 고객 상담, AI 비서 같은 업무를 자동화하고 자주 고칩니다.
- 기능 하나를 추가하는 작은 수정이 **다른 사람의 데이터를 지우거나 보게 만드는** 보안 문제를 만들 수 있습니다.
  - 실제 사례: 공개 프로젝트 n8n-claw에서 "기억 삭제" 기능을 추가한 수정에는 소유자 확인이 빠져 있었습니다. 그 도구 코드를 따로 돌려 본 재현에서 남의 기록도 지워졌습니다.
- 공개 검사 도구 5개로 같은 수정의 전후를 검사해 봤는데, 다섯 개 모두 위험한 버전과 고친 버전을 구별하지 못했습니다.
  - 이 도구들은 코드 안의 소유자 확인을 보지 않습니다.
  - 조사한 후보 중 n8n 워크플로의 전후 버전을 직접 실행해 비교하는 공개 도구는 하나였지만, 조사한 버전에서는 AI 노드를 지원하지 않아 n8n-claw를 실행하지 못했습니다.

## 어떻게 확인하나

| 단계 | 하는 일 |
|---|---|
| A. 변경 분석 | 전후 워크플로를 그래프로 비교해, 바뀐 부분이 어떤 데이터와 동작까지 영향을 주는지 찾습니다 |
| B. 시나리오 선택 | 알려진 취약 사례(카드)에서 이 변경에 맞는 시험 시나리오를 고릅니다 |
| C. 실행과 판정 | 같은 업무·같은 초기 데이터로 전후를 격리된 환경에서 실행하고, 워크플로 밖에서 남긴 기록으로 금지된 효과가 생겼는지 판정합니다 |

판정은 "위반 관측 / 위반 없음 / 판단 불가"로 나눕니다. 실행이 실패했거나 증거가 부족하면 **안전하다고 말하지 않습니다.**

## 지금 된 것 (11/12 기준)

- 변경 분석, 시나리오 검색, 정적 검사, 결과 저장이 구현되어 있습니다.
- 합성 주문 조회 사례를 실제 n8n(Docker)으로 전후 실행해 정상 업무 검사 24개를 통과했습니다.
- 독립 판정기와 자격시험 10개 사례를 구현해 검토 중입니다.
- 결과를 보여 줄 웹 서비스(GitHub 로그인, 결과 업로드, 공개 페이지)를 만들고 있습니다.

## 발표 때 보여 줄 것

1. 워크플로 하나를 "위험하게 고친 버전"과 "제대로 고친 버전"으로 실행합니다.
2. FlowDelta가 위험한 버전에서만 **남의 데이터에 접근한 기록**을 찾아냅니다.
3. 결과를 웹 페이지에서 간단 보기와 상세 보기로 확인합니다.

## 한계를 솔직하게

- n8n의 모든 기능을 지원하지 않습니다. 지원하지 않는 워크플로는 "지원 안 함"으로 표시합니다.
- 검사가 통과해도 그 조건에서 위반이 관측되지 않았다는 뜻이지, 완전히 안전하다는 증명은 아닙니다.
